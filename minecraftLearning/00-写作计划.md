# Minecraft 技术原理系列写作计划

> 本系列从**引擎与数据模型**视角拆解 Minecraft(以 Java 版为主)的底层原理:体素世界怎么组织、地形怎么靠种子和噪声生成、区块怎么渲染、世界怎么按 20 TPS 跑起来、数据怎么存盘,以及方块、方块实体、实体、流体、物品、生物群系、光照、注册表这一整套对象模型如何分层咬合;再往外讲到网络、渲染管线、玩法系统和扩展生态。
> 它不是"生存攻略"也不是"红石教程",而是面向工程师的"Minecraft 是怎么被造出来的"。

---

## 核心定位

很多人玩了几百小时 Minecraft,却从没想过这些问题:

- "无限世界"为什么不会把硬盘撑爆?
- 同一块地里的麦子为什么有的先熟有的后熟?
- 为什么离开后远处的农场和红石机器会停摆?
- 床、箱子这种看起来普通的方块,凭什么是"方块实体"?
- 一个坐标上到底叠着多少层数据?

本系列只回答一类问题:

> **把 Minecraft 当成一个软件工程作品,讲清楚它的数据模型、存储格式、运行循环和渲染策略,以及这些设计为什么是这样取舍的。**

因此本系列默认选择:

| 维度 | 选择 | 原因 |
| --- | --- | --- |
| 版本基线 | Java 版,以 1.18 引入的现代形态为基线;版本相关内容标注到 26.3(2026-09) | Anvil 存储、分段调色板、世界高度扩展、新世界生成都在 1.18 前后定型 |
| 视角 | 引擎 / 数据结构 | 不讲玩法技巧,讲"底层怎么实现的" |
| 深度 | 机制 + 字节级 + 取舍 | 关键处下沉到字节布局与算法,并解释为什么这样设计 |
| 边界 | 不逐行读源码 | 讲清结构与原理,源码类名作为指针给出 |

## 版本约定

- 正文讲的是 1.18 以来稳定的结构;某个机制在之后的版本里变过,就在原处用"版本说明"或括注写清"哪个版本起怎样"。
- Java 版的版本号在 2025 年底换了格式:最后一个 1.x 正式版是 **1.21.11**(2025-12),之后改为"年份.版本",依次是 **26.1、26.2、26.3**(2026-09,写作时的最新正式版)。快照里的变化只在必要时提及,并注明"尚未进入正式版"。
- 对本系列影响较大的版本变化汇总在第 26 篇第四节。

## 篇目设计(共 26 篇)

### 第一层:世界的生成与呈现 (01-03)

- **01 体素世界、区块与无限地形的存法** (block/voxel 网格 / Chunk 与 16³ Section / 为什么不能逐方块渲染 / "无限世界"靠确定性的按需生成:没去过的地方不存在,去过的区块整块存盘)
- **02 地形生成:种子、噪声与确定性世界** (Perlin 倍频叠加 / 种子+坐标→确定输出 / 气候参数与 3D 密度 / 分阶段生成流水线与 Status / 新旧地形断层与 1.18 地形混合)

### 第二层:世界怎么跑起来、又怎么存下来 (04-08)

- **05 区块的生命:加载、ticket 等级与模拟距离** (chunk 不是二元加载 / ticket level 距离场 / entity-ticking vs block-ticking vs border / simulation distance 与"128 格内有玩家"规则 / 为什么远处机器停摆 / 区块加载器与已移除的出生点区块)
- **06 实体系统:脱离网格的自由对象** (Entity vs 方块的本质差异 / 浮点坐标与 AABB 碰撞逐轴裁剪 / 实体层级 / A\* 寻路与 Goal/Brain AI / 1.17 起实体单独存储 / 实体为何是 lag 头号来源)
- **07 存储(上):Region/Anvil 文件格式逐字节** (为什么打包成 region / 8KB 头:位置表+时间戳表 / 4KB 扇区对齐 / 长度+压缩类型字节 / zlib/LZ4 / 超大 chunk 外置 .mcc / 扇区分配与碎片)
- **08 存储(下):NBT 与 Palette 位压缩** (NBT 标签布局与类型表 / chunk NBT 现代结构 / 局部调色板 + bit-packed Long_Array / bitsPerEntry 规则与内存里的四档调色板 / 1.16 前后跨界与不跨界 / DataVersion 与版本迁移)

### 第三层:世界由什么构成 (09-12)

- **09 方块的三层:Block、BlockState 与方块实体** (Block 单例=类型/行为 / BlockState=属性组合与全局调色板 / 为何方块无逐实例数据 / BlockEntity:存数据 vs 特殊渲染 / 床为何是方块实体 / 箱子的物品+开盖动画+大箱子双方块配对)
- **10 世界里还有什么:流体、物品、生物群系、光照、粒子** (FluidState 从 BlockState 读出、含水机制、独立 tick / ItemStack 寄生在容器 / Biome 4×4×4 粒度 / 光照双通道与洪水填充传播 / 粒子与声音纯客户端)

## 贯穿视角

全系列围绕一组反复出现的设计习惯展开,而不是堆砌孤立知识点:

> **Minecraft 的省与快,几乎都来自三招——没去过的不生成,能共享的不复制,必须存的压到最小。**

| 招式 | 典型体现 | 篇目 |
| --- | --- | --- |
| 没去过的不生成 | 地形靠种子+噪声确定性地按需生成;战利品箱打开时才生成物品;随机刻抽样代替逐格轮询 | 01 / 02 / 04 / 09 |
| 能共享的不复制 | 千万个石头共享一个 BlockState,格子只存调色板下标;FluidState 从方块状态读出;物品只存相对默认组件的差异 | 09 / 10 / 17 |
| 必须存的压到最小 | 局部调色板 + 位压缩,均质 section 压到近乎为零;1024 个区块打包进扇区对齐的 region 文件;内存与磁盘结构相近,加载转换便宜 | 03 / 07 / 08 |

**一个必须讲对的边界**:确定性生成省掉的是"还没去过的地方",不是"去过但没改过的地方"。Java 版的区块一旦生成就会整块写盘,存档大小正比于探索范围而不是改动范围(第 01、07 篇)。

## 单篇写作模板

每篇尽量遵循固定结构,避免变成散点知识:

```text
1. 问题定位
   - 这个机制要解决体素世界里的什么核心难题
   - 朴素做法为什么扛不住(性能 / 存储 / 一致性)

2. 设计与结构
   - 核心数据结构、对象或文件布局
   - 关键算法或运行流程

3. 下沉细节
   - 字节级布局 / 位运算 / 调度顺序等关键处展开
   - 版本演进带来的差异(标明版本号)

4. 取舍与边界
   - 为什么这样设计、牺牲了什么换了什么
   - 常见误解与反直觉点

5. 串联
   - 与前后篇、与贯穿全系列那组招式的呼应

6. 参考
   - minecraft.wiki 技术页面、官方文章、项目仓库;结论以这些来源为准
```
