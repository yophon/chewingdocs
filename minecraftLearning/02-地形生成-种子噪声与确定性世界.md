# 地形生成:种子、噪声与确定性世界

Minecraft 号称"无限世界",你可以朝一个方向走上几天,脚下永远有新地形冒出来。但这里有个绕不过去的工程矛盾:**无限的世界,装不进有限的硬盘**。如果地形是预先画好存下来的,那存到第几个 TB 才算"无限"?

答案是:**地形不是预先存好的。它是在你第一次走到时,被一个函数当场算出来的**——算出来之后,这块地才被存进存档。这一篇讲清楚这个函数怎么来的、为什么它能保证你和你朋友看到的世界一模一样,以及一块石头从"虚空"变成"真实方块"要经过哪些流水线阶段。

> 一句话先记住:**地形 = f(种子, 坐标)。同一个种子、同一个坐标、同一版本,永远算出同一个方块。** 所以没去过的地方不用存;去过的区块生成一次、整块存盘,以后直接读盘。生成是确定的,存储是按需的。

---

## 一、为什么不能"预先画好存下来"

先把朴素方案枪毙掉。假设我们像存图片一样存地形:

```
世界 = 一个超大三维数组
存盘 = 把整个数组写进文件
```

问题立刻爆炸:

| 朴素做法 | 后果 |
| --- | --- |
| 世界有限 | 那就不是"无限世界",走到边界就掉下去 |
| 世界无限 | 文件无限大,根本写不完也存不下 |
| 玩家只逛了 0.001% | 却要为 100% 的地形付出存储 |

真正的世界 99.99% 是玩家**从没去过、也永远不会改**的区域。为这些区域存数据,纯属浪费。于是设计目标变成:

> **没去过的地方不占一个字节;只有走到的地方,才生成、才占空间。**

要做到"走到哪生成到哪",而且今天生成的区块和下周才生成的隔壁区块能严丝合缝地接上,就需要一个**确定性函数**:给它一个坐标,它吐出那里应该是什么方块,而且不管什么时候、按什么顺序问,吐的都一样。这个函数的核心,就是**噪声(noise)**。

---

## 二、噪声:可控的随机

直接用 `random()` 生成地形是不行的——它给出的是**白噪声**,每个点和相邻点毫无关系,生成出来是一片杂乱的"电视雪花",不是山脉。

地形需要的是**平滑的随机**:相邻坐标的高度应该接近,整体又有起伏。这就是 **Perlin 噪声 / Simplex 噪声**解决的问题。

```
白噪声(random):        平滑噪声(Perlin/Simplex):
 █ ░ █ ░ ░ █ ░ █          ░ ▒ ▓ █ ▓ ▒ ░ ░
 ░ █ ░ █ █ ░ █ ░          ▒ ▓ █ █ ▓ ▒ ▒ ░
 像素级抖动,无地貌        连绵起伏,像山和谷
```

Minecraft Java 版实际用到的噪声:

| 噪声 | 在原版里的用途 |
| --- | --- |
| **Perlin 噪声**(代码里叫 `ImprovedNoise`,即 Ken Perlin 2002 年的改进版) | **地形生成的主力**。多个倍频叠成 `PerlinNoise`,再两两组合成 `NormalNoise`;1.18 的气候参数、密度函数基本都建在它上面 |
| **Simplex 噪声** | 只在少数地方出现,例如末地外岛的形状、生物群系温度的局部扰动 |
| **OpenSimplex** | 原版**从没用过**。它常出现在体素教程里,是为规避 Simplex 专利而写的开源变体 |

很多文章说"Minecraft 从 Perlin 换成了 Simplex",这是把通用体素教程的说法套到了原版头上。原版的地形一直是 Perlin 系的,变化的是"怎么组合这些噪声"(第 16 篇)。

噪声函数的关键性质,正是地形生成的命根子:

> `noise(x, z)` 是一个**纯函数**——只要输入坐标不变,输出永远不变,且与"先访问哪里、后访问哪里"无关。

这意味着你可以**乱序**地、**重复**地查询任意坐标,结果完全一致。地形因此可以"走到哪算到哪",不依赖任何已生成的历史。

## 三、种子:让"确定"可复制

光有噪声还不够。如果每个存档都用同一套噪声,所有世界就长得一模一样了。所以引入**种子(seed)**:

```
最终地形 = noise(seed 扰动后的坐标空间)
```

种子的作用是**给噪声函数换一套坐标偏移/排列**,于是:

- **同一个种子** → 同一个世界。你把种子发给朋友,他生成出的出生点、村庄、地形和你**逐方块相同**(同版本下)。
- **不同种子** → 完全不同的世界。

这就是为什么社区里能流传"种子号":一串数字就完整编码了一个无限世界的全部原始地貌。**还没被探索的那部分世界,信息量全压缩在"种子 + 生成算法"里**,不占文件里的一个字节。

```
你的存档真正存的:
  ┌──────────────────────────────────────────┐
  │ 种子(决定所有还没生成的地方长什么样)    │  ← 几个字节
  │ + 已经生成过的区块(整块、压缩后存)      │  ← 正比于你探索过的范围
  └──────────────────────────────────────────┘
没去过的地方 = 0 字节,第一次走到时才用种子算出来
```

注意右边第二行写的是"已经生成过的区块",不是"你改动过的方块"。区块一旦生成就会整块存盘,以后再加载都是读盘,不会重算(第 01 篇第三节讲了原因)。

## 四、多层噪声叠加:从一条曲线到一个世界

单层噪声只能给你一种尺度的起伏——平滑但单调。真实地形要同时表达**大尺度的山脉**和**小尺度的碎石起伏**。做法是**多层噪声叠加(octaves)**。下面用最好懂的"高度图"写法演示这个思路(Minecraft 真实的做法是三维的,本节末尾会说):

```
高度(x,z) =  1.0 * noise(x/256, z/256)   // 低频:大陆、山脉走向
          + 0.5 * noise(x/64,  z/64)    // 中频:丘陵
          + 0.25* noise(x/16,  z/16)    // 高频:地表碎起伏
          + ...
```

工程直觉就三个旋钮:

| 旋钮 | 含义 | 调大的效果 |
| --- | --- | --- |
| **频率 frequency** | 坐标被除以的尺度 | 频率高 → 起伏密集、细碎 |
| **振幅 amplitude** | 这一层的权重 | 振幅大 → 这一层主导地貌 |
| **octave 层数** | 叠几层 | 层多 → 既有大山又有细节 |

通常每加一层,**频率翻倍、振幅减半**(这种叠加方式叫 fractal/fBm)。低频层管"大势",高频层管"细节",叠起来就有了既宏观又精致的地貌。

### 不只是高度:气候场

Minecraft 现代地形(1.18 重写后)不是只算一个高度,而是同时算**好几张独立的噪声场**,再用它们共同决定每个位置:

```
温度场 temperature ─┐
湿度场 humidity    ─┤
大陆度 continentalness ─┼──►  查"气候 → 生物群系"表  ──►  这里是沙漠?雪原?丛林?
侵蚀度 erosion    ─┤
怪异度 weirdness  ─┘
(再加一个由高度推出来的 depth,一共 6 个参数,第 16 篇展开)
```

- **生物群系不再是"先画板块再填"**,而是"算出这点的气候坐标,再去多维表里查它落在哪个 biome"。
- 同一套噪声框架还驱动 1.18 的**巨型矿脉**和**噪声洞穴**(用 3D 噪声直接在实心区域"挖空"出隧道与巨洞,即所谓 noise caves)。普通的零散矿石则仍是按随机规则撒下去的 feature。

注意一个维度差异:大陆度、侵蚀度这类管"大势"的参数是 **2D 噪声**(每个 x,z 一个值);而真正决定"这一点是石头还是空气"的是一个 **3D 密度**(每个 x,y,z 一个值)。上面那个"高度图"公式只是教学用的简化——Minecraft 从早期起就是按三维密度来填方块的,所以才会有 2D 高度图永远做不出的悬崖、悬空洞穴和拱桥。3D 更贵,这也是世界生成吃 CPU 的原因之一。

## 五、生成是分阶段的流水线,不是一锤子

你可能以为"生成一个 chunk"是一个原子操作:输入坐标,输出完整地形。**不是。** 因为有些结构是**跨 chunk** 的——一个村庄、一条洞穴、一棵树,可能横跨好几个 chunk 的边界。

如果每个 chunk 各自独立地"一次性生成完",边界处就会对不上:村庄被切成两半、洞穴在 chunk 边界突然截断。

为了解决这个,Minecraft 把生成拆成**一连串阶段(ChunkStatus)**,每个 chunk 像在流水线上一格格往前走(以 1.20+ 为准):

```
empty                  (还什么都没有)
  → structure_starts     (决定这里要不要起一个村庄/要塞,并定好整座结构的布局)
  → structure_references (登记"附近有哪些结构会伸进我这块")
  → biomes               (确定生物群系)
  → noise                (用噪声填出石头/空气/水的基础地形)
  → surface              (铺地表:草、沙、雪)
  → carvers              (老式雕刻器挖洞穴、峡谷)
  → features             (放结构的方块、撒树木、矿石、植被)
  → initialize_light     (准备光照数据)
  → light                (计算光照)
  → spawn                (生成时自带的初始动物)
  → full                 (完工,变成可被游戏逻辑使用的正式区块)
```

不同版本的阶段列表略有不同:1.18–1.19 还有 `liquid_carvers`、`heightmaps`;最新的 26.3 又把 `noise`、`surface`、`carvers` 三步合并成了一个 `terrain` 阶段。但"分阶段推进、阶段之间有邻居依赖"这个思路一直没变。

关键约束:

> **一个 chunk 要推进到某些阶段,它周围一定范围内的邻居必须先推进到指定阶段。**

比如要给中心 chunk 跑 `features`(种树、把村庄房子盖上去),引擎要保证它周围一圈邻居至少都到了 `carvers`,这样跨边界的树冠、房子才能正确地"画"到邻居身上。这就是为什么生成新区域时,引擎实际上在**同时推进一整片 chunk 的阶段**,像一个向外扩散的波纹,而不是孤立地一个一个生成。

```
中心要 features,必须邻居先就位:

  carvers carvers carvers
  carvers [feat]  carvers     ← 中心能种跨界的树/村庄,
  carvers carvers carvers        是因为外圈已经有地形可以"画"上去
```

正因为有这些依赖,在你已探索区域的边缘,经常有一圈"生成了一半"的区块(停在 features 之前的某个阶段)。它们同样会被存进存档,存档里的 `Status` 字段就记着它们走到了哪一步(第 08 篇)。

这也是"卡在生成区块"(Building terrain / 加载卡顿)的根源之一:不是算一个 chunk 慢,而是要把一大片邻居都拉到对应阶段才能交付中心那一个。

## 六、踩坑与反直觉

**1. "重新生成会不会把我家删了?"**
不会。已经生成过的区块是从磁盘读出来的,根本不会重新生成;生成只发生在"磁盘上还没有这个区块"的时候。反过来,如果你用工具把某个区块从 region 文件里删掉,下次走到时它会按种子重新生成成原始地形——你在那里盖的东西就真没了。这正是"删区块重置地形"的原理。

**2. 同种子不同版本,世界不一样。**
确定性只在**同一版本的生成算法**下成立。Minecraft 大版本经常重写地形(最著名的是 1.18 把地形和洞穴生成整个换掉),所以同一个种子在 1.16 和 1.18 里完全是两个世界。跨版本打开老存档时,已经生成过的区块保持原样(只做数据格式升级,第 17 篇),只有没生成过的区块才用新算法——于是老世界里常见一条"地形断层带",正是新旧生成算法在你当年探索边界处接缝的痕迹。1.18 为此专门加了**地形混合(blending)**,让新生成的地形在边界处向旧区块平滑过渡,断层不再那么生硬。这条现象本身也说明了:区块是整块存下来的,而不是"存改动、其余重算"。

**3. 生物群系不是"画"出来的板块。**
别用"先有一张生物群系地图、再填地形"的旧心智。现代实现是反过来的:**先有连续的气候噪声场,生物群系是气候坐标的查表结果。** 所以 biome 边界其实是噪声等值线,过渡自然而非硬切。

**4. 洞穴为什么有的是细管、有的是巨洞?**
因为它们来自 3D 噪声 + 雕刻器(carver)两套机制叠加。3D "奶酪/面条"噪声负责大尺度空腔,carver 负责蜿蜒隧道,两者尺度不同,叠出来就有粗有细。

**5. 噪声查询是无副作用的,可并行。**
正因为 `noise(x,z)` 是纯函数、不依赖访问顺序,地形生成天然适合多线程:原版的生成任务本来就跑在后台工作线程上,不同 chunk 的 `noise` 阶段可以各算各的。难并行的是 `features` 这类要读写邻居区块的阶段——依赖多、要协调,C2ME 这类优化 mod 主要就在这里下功夫(第 19 篇)。

## 七、串联

把这一篇放回整条主线:

- **承接 01(体素世界)**:上一篇说"世界由 chunk 和 16³ section 的方块网格组成,但无限世界不可能预先造好"。这一篇就是那句话的下半段——**网格里每个方块的初始值,在你第一次走到时由种子+噪声当场算出**,所以"无限"才成立。
- **接着 03(渲染)**:噪声只决定"每格是什么方块",算完得到的是一片纯数据的方块网格;怎么把这堆方块**高效画到屏幕上**(只画看得见的面、合并成 mesh),是渲染篇的事。
- **呼应 07/08(存储)**:生成和存储的分工,正是本系列主线的第一招——"没去过的不生成"。没去过的地方由种子决定,不占空间;去过的区块生成一次就整块存盘,以后读盘不再重算。区块 NBT 里的 `Status` 记着它生成到了哪一步,`DataVersion` 记着它最后被哪个版本写过,存储篇会再展开。

一句话收束:**种子是所有"还没去过的地方"的全部信息,噪声是把它展开成地形的函数,流水线阶段是让跨区块结构不破缝的工程手段。三者合起来,"无限世界 + 有限硬盘"这个矛盾才不再矛盾。**
