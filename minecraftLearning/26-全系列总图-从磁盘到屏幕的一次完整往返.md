# 全系列总图:从磁盘到屏幕的一次完整往返

第 12 篇画过一张"前半程总图",但它只覆盖**世界本身**:服务端那一侧的数据模型、运行循环和存储。后半程的第 13–25 篇又往外铺了几层:世界怎么经过网络、资源包和渲染管线到达玩家,建在数据模型之上的红石、刷怪、AI、指令,还有 Bedrock 对照、性能诊断、mod 生态和维度。

这一篇是全系列的收口,只做三件事:**把所有层合成一张图;用一次完整的往返——你在服务器上放下一块石头——把几乎每一篇串起来;最后回到那组贯穿全系列的招式,并列出截至 26.3 正在变化的地方。**

> 一句话先记住:**Minecraft 是"服务端上的一个分层世界 + 客户端上的一条渲染管线",中间用一条分阶段的网络协议连着;注册表是贯穿两端的主轴,而"没去过的不生成、能共享的不复制、必须存的压到最小"是贯穿全系列的设计习惯。**

## 二、一次完整往返:你在服务器上放下一块石头

下面这一趟,几乎会碰到系列里的每一篇。

```
① 客户端:你按下右键                                              (13)
   客户端确认手里有方块、准星指着某个面
   → 发一个"对方块使用物品"的包;可能先在本地显示一下,但以服务端为准

② 服务端:裁决                                                    (13 · 11)
   包里的物品、方块都是运行时数字 ID
   检查距离、权限、这格能不能放 → 通过

③ 服务端:改世界                                                  (09 · 08 · 10)
   setBlock(pos, 石头的 BlockState, 标志位)
   → 找到 pos 所在 section 的 PalettedContainer
   → 石头不在调色板里?加进去;种类超过 16 种?4 bit 扩成 5 bit,重排数组
   → 这一格原来是水?FluidState 也跟着变成空——它本来就是从 BlockState 读出来的
   → 区块标记为"未保存"

④ 服务端:连锁反应,全在本 tick 的 50ms 预算里                     (04 · 14 · 10)
   邻居通知:周围方块重算(红石线更新强度、火把检查自己还挂不挂得住)
   光照:这格变成不透明 → 光照引擎重新传播 BlockLight / SkyLight
   游戏事件:发出一次"放置方块"的振动,附近的幽匿感测体能收到

⑤ 服务端 → 客户端:同步                                           (13 · 05)
   给所有"能看到这个区块"的玩家发方块更新包,以及光照更新
   谁能看到,由渲染 / 视距决定,和模拟距离无关

⑥ 客户端:变成画面                                                (22 · 03 · 20)
   客户端改自己那份区块数据 → 把这个 section(在边界的话连同邻居)标脏
   worker 线程重建 mesh:
     每格取 BakedModel(blockstate → 模型 → 图集,第 22 篇)
     按 cullface 剔掉被挡住的面(第 03 篇)
     算平滑光照与 AO,按 RenderType 分桶
   上传 GPU;下一帧经过视锥剔除 + cave culling(第 20 篇),石头出现在屏幕上

⑦ 之后某个时刻:存盘                                              (07 · 08 · 12)
   自动保存 / 卸载时:按实际内容整理调色板 → NBT → zlib → 写进 .mca 的空闲扇区
   下次加载:读扇区 → 解压 → 解析 NBT → 方块名查注册表 → 重建 PalettedContainer
```

几个值得停下来看的点:

- **两份世界**:服务端那份是真相,客户端那份是"副本 + 渲染缓存"。①⑤⑥ 之间的每一次延迟,都是这两份之间的时间差(第 13 篇)。
- **数字和名字**:②⑤ 里方块是数字 ID,⑦ 的磁盘上是方块名。注册表在两头分别扮演"快"和"稳"两个角色(第 11 篇)。
- **同一个"调色板"心智出现了三次**:③ 内存里、⑦ 磁盘上、⑥ mesher 读数据时。这就是第 03、08 篇反复说的"内存与磁盘结构相近"。
- **最贵的往往不是这一块石头**,而是它引出的连锁反应和成千上万个同时在动的实体——第 19 篇讲怎么测出来到底是谁在吃 tick。

## 三、贯穿全系列的那组招式

> **没去过的不生成,能共享的不复制,必须存的压到最小。**

前半程第一次提出它时,例子都在服务端的世界里。后半程你会发现,同样的习惯在网络、渲染、资源、物品模型里一再出现:

| 招式 | 前半程(01–12) | 后半程(13–26) |
| --- | --- | --- |
| **没去过的不生成**(推广:不需要的就不算) | 种子 + 噪声按需生成(02);战利品箱打开时才生成物品(09);随机刻抽样代替逐格轮询(04);区块等级只给玩家附近花算力(05) | 刷怪只在玩家 24–128 格的壳里尝试(15);视锥 + cave culling 只画看得见的(20);结构先定"图纸",方块后盖(16) |
| **能共享的不复制** | BlockState 共享 + 调色板下标(09);FluidState 从方块状态读出(10);注册表单例(11) | 物品"默认组件 + 只存差异"(17);父模型、旋转复用模型,图集共享一张纹理(22);已知数据包不重复发送(13) |
| **必须存的压到最小** | 局部调色板 + 位压缩,单值 section 省掉数组(08);region 打包 + 扇区对齐(07) | 网络只发增量、实体没动就不发(13);光照只用 4 bit 一格(10) |

也有一个醒目的反例:**实体**。它不能共享、位置必须显式存、每个都得每 tick 单独跑(第 06 篇)——所以 Minecraft 的性能问题,十有八九最后都落到"在场实体太多"上(第 19 篇)。理解了招式,也就理解了它的边界。

还有一个值得记住的对照:Bedrock 版(第 18 篇)用完全不同的技术栈——C++、LevelDB、RakNet、服务端权威移动——重写了同一个游戏,但"体素网格 + 区块 + 调色板、确定性生成、固定 tick、客户端/服务端分离"这些骨架一样不少。两版都绕不开的,才是问题本身的形状。

## 四、它正在怎样变化(截至 26.3)

本系列以 1.18 引入的现代形态为基线。从那以后,有不少改动碰到了前面讲过的机制,下面按版本列出(Java 版从 2026 年起改用"年份.版本"的新编号,1.21.11 之后的下一个正式版是 26.1):

| 版本 | 变化 | 相关篇目 |
| --- | --- | --- |
| 1.20.2 | 协议新增 Configuration 阶段 | 13 |
| 1.20.3 | `/tick` 命令 | 04 · 19 |
| 1.20.5 | 物品改为数据组件;region 可选 LZ4;出生点区块范围可调 | 17 · 07 · 05 |
| 1.21 | 数据包目录去复数;袭击改由不祥之瓶 / 袭击之兆触发 | 21 · 23 |
| 1.21.2 | `food` / `consumable` 拆分;lightmap 改由着色器计算 | 17 · 20 |
| 1.21.4 | 物品模型定义(`assets/<ns>/items/`) | 22 |
| 1.21.5 | 随机刻不再要求附近有玩家;渲染器改写到 GpuDevice 抽象之后 | 05 · 20 |
| 1.21.9 | 移除出生点区块 | 05 |
| 1.21.11 | 最后一个混淆版本;环境属性与时间线 | 24 · 25 · 04 |
| 26.1 | 不再混淆;世界时钟;渲染层按贴图自动判定 | 24 · 04 · 20 |
| 26.2 | Vulkan 以实验性功能上线 | 20 |
| 26.3 | `noise` / `surface` / `carvers` 合并为 `terrain` 阶段;调色板键名改小写 | 02 · 08 |
| 26.4 快照 | 默认优先 Vulkan;生物群系改为逐方块存储(尚未正式发布) | 20 · 10 |

变的大多是实现细节和数据格式;不变的是本系列讲的骨架。以后读更新日志时,可以拿第一节那张图定位"这次改的是哪一层",再回到对应的篇目看它牵动了什么。

## 五、往下读什么

- **minecraft.wiki 的技术页面**:Chunk format、Tick、Mob spawning、Region file format 这类页面写得极细,是本系列大部分细节的出处;每篇末尾的"参考"都列了对应页面。
- **游戏本身的代码**:26.1 起 Java 版不再混淆,反编译出来就是 Mojang 起的类名和方法名(`PalettedContainer`、`ServerChunkCache`、`PortalForcer`……)。本系列提到的类名,都可以直接搜。
- **优化 mod 的源码**:Lithium、Sodium、C2ME 的提交记录,本身就是一部"原版哪里慢、为什么慢"的注解。

这就是这个系列想留给你的东西:不是答案的清单,而是一张能自己推出答案的地图。
