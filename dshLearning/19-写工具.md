# 写工具

13 篇站在管线的角度看一次工具调用:pre-execute → guard → execute → post-execute → result。这一篇换到工具作者的角度:一个工具要声明什么、`execute` 要遵守什么、哪些事不该写在工具里。18 篇的开发循环在这里照常适用,把工具插件挂进 overlay、重启 Web 就能让模型调用。

和 Claude Code 对照:Claude Code 的自定义工具主要通过 MCP server 接入,权限靠 settings 里的规则。dsh 里工具就是进程内的 Cordis 插件,`ctx.tools.register()` 一行注册;MCP 工具也是同一个注册表里的普通条目。

> 一句话先记住:**工具只负责"做事,并返回一个规范的 JSON 值"**。给模型看的文字由 `output.render` 生成,UI 卡片由 presenter 描述,而审批、超时、审计都在工具之外完成。`ToolDefinition` 上没有"危险等级"或"需要审批"这类字段,审批是策略,靠 `tools/pre-execute` 监听器决定。

## 一、最小的工具

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name.',
    parameters: {
      name: { type: 'string', required: true, description: 'The name to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))
}
```

用 18 篇的 overlay 挂进去,`pnpm dsh web --patch ./scratch-plugin/cordis.yml` 重启,在 Web 里说"Use the greet tool to greet Ada.",模型会调用 `greet` 并收到 `Hello, Ada!`。

这几行里已经有三个关键点:

- `inject: ['tools']` 让插件等工具注册表就绪
- `ctx.tools.register()` 返回 disposer 并挂到插件的 effect 上,插件卸载时工具自动注销
- schema 自动进入 system prompt 组装,不需要手动接线

## 二、ToolDefinition 字段一览

| 字段 | 必需 | 发给模型 | 作用 |
| --- | --- | --- | --- |
| `name` | 是 | 是 | 全局唯一。`run_code` 是保留名,不能注册 |
| `description` | 是 | 是 | 模型看到的说明 |
| `parameters` | 是 | 是 | `defineTool` 里是参数 DSL,编译成 JSON Schema |
| `output.schema` | 是 | 否 | 规范返回值的 schema,每次成功返回都会校验 |
| `output.render(args, value)` | 是 | 否 | 把规范值投影成给模型的内容块 |
| `output.presentationMeta(args, value)` | 否 | 否 | 投影出可回放的 UI 数据,持久化在 `tool/result` 上 |
| `execute(args, exec)` | 是 | 否 | 执行体,只返回规范值 |
| `timeoutMs` | 否 | 否 | 协作式超时预算,由 `dsh-tool-call-timeout-policy` 执行 |
| `isConcurrencySafe(args)` | 否 | 否 | 只有返回 `true` 才允许和同一响应里的其他调用并行 |
| `presentCall` / `presentResult` | 否 | 否 | 纯函数,描述 UI 卡片 |
| `deferLoading` | 否 | 是 | 请求延迟加载工具定义,提供方是否支持见 LLM 包的限制说明 |

注册表在请求时只把 `name`、`description`、`parameters`(以及 `deferLoading` 标记)投影成 `ToolSchema` 发给模型,其余字段不会出现在请求里。缺 `output` 或 `output.render` 不是函数,`register()` 直接抛 `TypeError`。

## 三、参数与输出

### 3.1 参数 DSL

`parameters` 是一个属性表,本身就是一个隐式的、开放的 object 根:

| 写法 | 含义 |
| --- | --- |
| `{ type: 'string', required: true }` | 必填字符串。不写 `required` 默认可选 |
| `{ type: 'string', enum: ['fast', 'full'] }` | 字面量约束,推断成联合类型 |
| `{ type: 'integer' }` / `{ type: 'number' }` / `{ type: 'boolean' }` / `{ type: 'null' }` | 标量 |
| `{ type: 'array', items: {...} }` | 数组,省略 `items` 接受任意 JSON |
| `{ type: 'object', properties: {...}, additionalProperties: false }` | 嵌套对象,**`additionalProperties` 必须显式写** |
| `{ type: 'json' }` | 任意无损 JSON |
| `{ oneOf: [a, b] }` | 恰好匹配一个分支,至少两个分支 |

`execute` 收到的 `args` 由这张表推断出类型,而且在执行前已经校验过类型、必填、字面量约束和嵌套结构。DSL 表达不了的约束(非空字符串、正数、字段之间的关系)要自己检查。注意 `default` 只是注解,**不会**替你填值,可选参数在 `args` 里仍可能是 `undefined`。

### 3.2 输出:一个规范的 JSON 值

`execute` 只返回 `output.schema` 声明的那个值。注册表会把它快照成无损 JSON、校验、冻结,再交给 `output.render` 生成给模型的内容。不要在执行体里直接返回内容块,也不要让调用方从一段文字里解析 id 和字段。

这样设计是为了 PTC(14 篇):在 PTC 模式下,`await tools.<name>(args)` 拿到的就是这个规范值,而不是渲染后的文字。所以 `output.schema` 应该当成一个程序化 API 来设计:句柄和字段直接返回,根节点可以是对象、数组、标量或 null,给人看的解释放进 `render`。

失败的处理:

- **基础设施失败就抛**。注册表会捕获,变成 `isError` 的结果,这一轮不会因此中断
- **领域内的"不理想结果"放进规范值**。比如进程非零退出,是一次成功的执行,退出码是值的一部分
- 返回值不符合 schema、`render` 抛错,都会变成 `INVALID_TOOL_OUTPUT` 错误

### 3.3 直接注册 JSON Schema 工具

`ctx.tools.register()` 也接受原始 JSON Schema 形式的 `ToolDefinition`,MCP server 发现的工具就是这样注册的(22 篇)。`defineTool` 只是给第一方工具用的类型化助手。直接注册时,参数校验由你自己负责。

## 四、`execute` 的契约

`execute(args, exec)` 的第二个参数 `exec` 携带执行身份和控制手段:

| 字段 / 方法 | 用途 |
| --- | --- |
| `exec.signal` | 调用方的取消信号,**必须遵守**:传给 `fetch`、子进程或 SDK,取消时尽快收尾 |
| `exec.callId` / `exec.name` / `exec.arguments` | 只读的调用身份,参数在策略开始前就已冻结 |
| `exec.agent` | 代表哪个 agent 调用。异步通知可以用 `agent.inject()` 追加到下一次请求 |
| `exec.deferContext(message)` | 把一段上下文挂到本次结果上,在 `tool/result` 之后追加 |
| `exec.concludeTurn()` | 标记成功结果为本轮终点,这一步结束后主循环停止 |

几条硬规则:

- **遵守 `exec.signal`**。注册表不会丢下你的 promise,也没法强杀同进程代码,执行体要在信号触发后到达静止状态再返回
- **把 `args` 当只读**。参数已经记进日志、展示给用户了,改它只会造成不一致
- **用 `agent.inject()` 时声明来源**。`source.kind` 要通过 `MessageSourceMap` 声明合并注册,会话格式 v4 会拒绝旧的 `{ kind: 'plugin', plugin: '...' }` 写法。agent 可能已经销毁,调用要包 try/catch
- **`inject()` 不会唤醒 agent**。空闲的 agent 收到 inject 仍然空闲,内容只在下一次请求里出现

## 五、一个更完整的例子

下面这个 `http_status` 工具对 URL 发一个 HEAD 请求,返回结构化结果,并用上了并发、超时和卡片:

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'http-status-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'http_status',
    description: 'Send a HEAD request and report the HTTP status of a URL.',
    parameters: {
      url: { type: 'string', required: true, description: 'Absolute https URL' },
    },
    output: {
      schema: {
        type: 'object',
        additionalProperties: false,
        properties: {
          url: { type: 'string', required: true },
          status: { type: 'integer', required: true },
          ok: { type: 'boolean', required: true },
          contentType: { type: 'string', required: true },
        },
      },
      render: (_args, v) => [{ type: 'text', text: `${v.status} ${v.ok ? 'OK' : 'NOT OK'} ${v.url}` }],
    },
    timeoutMs: 15_000,                   // 由 base 里的 timeout-policy 执行
    isConcurrencySafe: () => true,       // 只读,不改共享状态
    presentCall: args => ({ card: 'generic', title: `HEAD ${args.url}`, kind: 'fetch' }),
    async execute(args, exec) {
      if (!args.url.startsWith('https://')) throw new Error('only https URLs are accepted')
      const res = await fetch(args.url, { method: 'HEAD', signal: exec.signal })
      return {
        url: args.url,
        status: res.status,
        ok: res.ok,
        contentType: res.headers.get('content-type') ?? '',
      }
    },
  }))
}
```

- **非 2xx 不抛错**:404 也是一次成功的检查,状态码在值里,模型和 PTC 程序都能直接读 `status`
- **`timeoutMs` 本身只是声明**:注册表从不执行截止时间,真正执行的是 `@deepseek-ai/dsh-tool-call-timeout-policy` 这个 `tools/execute` 包装器。base bundle 里有这一行(id `timeout-policy`),自定义组合要自己挂上。声明 `timeoutMs` 等于承诺执行体会把 `exec.signal` 传下去
- **`isConcurrencySafe`**:只有显式返回 `true` 才进入并行组。省略、抛错、返回非 `true` 都按独占处理。并行的调用不能修改父级持有的状态
- **网络请求不经过沙箱**:这是插件进程里的 `fetch`,05 篇讲的沙箱包的是子进程。想限制访问哪些主机,用第六节的策略监听器

## 六、审批是策略,不是工具属性

### 6.1 为什么没有审批字段

同一个工具,在 CI 里可能要一律拒绝,在本机交互时要问人,在受信任的容器里可以直接放行。这是部署策略,和工具实现无关。所以 dsh 把它放在管线上:`tools/pre-execute` 返回 `PreToolDecision`,`ctx.tools.guard()` 加最终禁令,`ask` 交给 `ctx.approval` 去问人(05 篇)。

### 6.2 策略监听器

```ts
import type { Context } from '@deepseek-ai/cordis'
import type { PreToolDecision } from '@deepseek-ai/dsh-tools'

export const name = 'http-allowlist'
export const inject = ['tools']   // 用到 ctx.tools.guard()

export function apply(ctx: Context) {
  // 可重排的策略层:非白名单主机要人确认
  ctx.on('tools/pre-execute', async (exec, next): Promise<PreToolDecision> => {
    if (exec.name === 'http_status') {
      const { url } = exec.arguments as { url: string }
      if (!url.startsWith('https://api.example.com/')) {
        return { kind: 'ask', reason: `request to ${url}` }
      }
    }
    return next()
  })

  // 单调禁令:后面的监听器无论返回什么都推翻不了
  ctx.tools.guard(exec =>
    exec.name === 'http_status' && String((exec.arguments as { url?: unknown }).url).includes('169.254.169.254')
      ? 'metadata endpoint is blocked'
      : undefined)
}
```

`PreToolDecision` 有四种:

| 决定 | 结果 |
| --- | --- |
| `{ kind: 'allow' }` / 调用 `next()` | 放行,交给下一个监听器 |
| `{ kind: 'deny', reason, info? }` | 拒绝,`reason` 作为错误结果给模型 |
| `{ kind: 'cancel' }` | 按取消处理,不显示成策略拒绝 |
| `{ kind: 'ask', reason?, displayReason? }` | 只有审批服务返回 `allowed-once` 才执行,其余情况拒绝 |

几点要注意:

- **waterfall 监听器必须调 `next()`**,忘了调等于短路掉后面所有策略
- **`ask` 的结果取决于会话的审批策略**:`never` 不会问任何人,直接 `rejected`;没有可用的审批渠道是 `unavailable`,同样拒绝。全部是 fail-closed
- **pre-execute 不能改写参数**,这是有意的限制,改写会让日志里的参数和实际执行的参数不一致
- **guard 是同步的**,返回字符串就拒绝,返回 `undefined` 不表态,没有"允许"这个返回值,所以监听器的顺序翻转不了它的拒绝

其余三个扩展点:`tools/execute` 包住 dispatch 做超时、重试、计量;`tools/post-execute` 改写结果或附加上下文;`tools/result` 只读观察最终结果。顺序和失败语义见 13 篇。

## 七、长任务:后台 job

要让命令在后台跑、agent 继续干别的,把工作交给 `ctx.jobs`:

```ts
declare module '@deepseek-ai/dsh-jobs' {
  interface JobKindMap { report: 'report' }
}

// execute 内部:
const jobs = ctx.get('jobs')
if (!jobs) throw new Error('background jobs unavailable')
const jobId = jobs.start({
  kind: 'report',
  label: `build report for ${args.target}`,
  owner: exec.agent?.id,               // SessionId;省略则任何调用方可见
  run: (job) => {
    const ctl = new AbortController()  // 任务自己的取消信号,不是 exec.signal
    const done = buildReport(args.target, ctl.signal, line => job.append(line, { channel: 'stdout' }))
      .then(() => ({ status: 'completed' as const }),      // done 永不 reject
        (e: unknown) => ({ status: ctl.signal.aborted ? 'killed' as const : 'failed' as const, detail: String(e) }))
    return { cancel: () => ctl.abort(), done }
  },
})
return { kind: 'background', jobId }
```

(`buildReport` 代表你自己的长任务函数。)

- **`kind` 要先声明**:`JobKind` 来自可合并的 `JobKindMap`,id 形如 `report-<16 位 hex>`
- **`owner` 是会话 id**。cookbook 里写的是 `owner: exec.agent`,但 `JobSpec.owner` 的类型是 `SessionId`,仓库里的 `tool-workflow` 传的是 `parent.id`。作业按 owner 隔离,别的 agent 读不到也停不了
- **`run()` 同步返回 `{ cancel, done }`**:`cancel` 必须同步、幂等;`done` 不能 reject,要在资源释放之后才 settle
- **id 发布之后,取消用任务自己的信号**。外层调用被取消只是不再等待,不会杀掉已发布的作业,停止归 `job_kill`、owner 销毁和服务销毁管
- **需要有控制器**:组合里要有 `@deepseek-ai/dsh-jobs-local` 和 `@deepseek-ai/dsh-tool-jobs`。后者提供 `job_output`、`job_list`、`job_kill` 和完成通知,没有它 `start()` 会直接失败
- **用配置开关 `run_in_background`**:cookbook 建议由插件配置决定是否暴露这个参数,`dsh-tool-bash` 的 `enableRunInBackground` 是现成的例子

成功的后台分支返回 `{ kind: 'background', jobId }` 这样的类型化句柄。`render` 里可以写"started background job ..."给人看,但 PTC 程序要从值里拿 id,不能去解析这句话。

## 八、PTC 模式白送

PTC 模式下(14 篇),每个可见的已注册工具都自动变成 `await tools.<name>(args)`,不需要任何额外集成。生成的 `ToolArgsMap` / `ToolOutputMap` 从同一份 schema 推出参数和返回值类型。子调用照样走完整管线,策略、guard、审批一个不少。成功的子调用 resolve 成经过策略之后的规范值,失败的子调用 reject 一个 `ToolCallError`,程序只能看到它的 `name`、`toolName` 和 `message`。

中间值只存在于本次执行,不进日志、不截断、没有字节上限,只有外层 `run_code` 的结果受输出上限和 spill 管线约束。工具返回大值时,程序的内存是真实成本。

## 九、UI 卡片

`presentCall` / `presentResult` 返回带 `card` 标签的渲染意图:

| 卡片 | `presentCall` | `presentResult` | 内置例子 |
| --- | --- | --- | --- |
| `generic` | 默认。`title`、`kind`(图标)、`rawInput`、`locations` | 可选标题和内容 | 大多数工具 |
| `terminal` | 调用本身就是 shell 命令 | 原始输出和退出信息 | `bash` |
| `diff` | 创建或修改文件,`diffs` 从参数推出 | 实际应用的 hunk | `write` / `edit` |
| `read` | 无(挂起时是 generic) | 文件窗口,来自 `result.meta` | `read` |
| `search` | 无 | `shape: 'matches'` 或 `'paths'` | `grep` / `glob` |
| `web` | 无 | `kind: 'search'` 或 `'fetch'` | `web_search` / `web_fetch` |

`kind` 的取值是 `read`、`edit`、`delete`、`move`、`search`、`execute`、`fetch`、`other`。

硬规则:

- **必须是纯函数**。它们在实时流和会话日志回放时都会运行,不能做 I/O、读会话状态、读时钟或随机数。需要结果时刻的事实,用 `output.presentationMeta` 投影进持久化的 `result.meta`
- **UI 格式不进模型结果**。fenced console 块、diff、相对路径都不该为了 UI 塞进规范值或 render 输出
- **`defineTool` 对展示路径做软校验**。旧日志里的参数不匹配时返回 `undefined`(回落到 generic),不会抛错

**内置 Web Client 不消费 `presentCall` / `presentResult`**。它通过 `tool.call.toolview` 这个 keyed slot 选择渲染器,从原始参数、结果内容和持久化的 `meta` 推导卡片属性。只在 Host 侧写 presenter,不会让 Web 多出一张专门的卡片;要专门的 Web 卡片,得另写浏览器端插件注册这个 slot(浏览器端打包见 20 篇)。

## 十、测试

仓库的测试策略(`docs/testing.md`)是:**只 mock 昂贵或不确定的边界**(LLM adapter、网络、时钟),下游保持真实。对工具来说,最轻量的验证方式是 Cordis 教程第 7 章的做法:不接模型,直接驱动真实的执行管线。

```ts
import { brandString } from '@deepseek-ai/dsh-brand'
import type { ToolCallId } from '@deepseek-ai/dsh-llm'

const result = await ctx.tools.execute({
  callId: brandString<ToolCallId>('demo-1'),
  name: 'greet',
  arguments: { name: 'Cordis' },
  signal: new AbortController().signal,
})
// result.isError / result.value / result.content
```

这条路径会经过 pre-execute、guard、执行体、post-execute 和 `tools/result`,参数校验和输出校验也都是真的。在教程那样不带 base 的独立组合里,至少要有 `@deepseek-ai/dsh-system-prompt` 和 `@deepseek-ai/dsh-tools` 两行:工具注册表依赖 `systemPrompt` 服务,缺了它会一直停在 PENDING。

`packages/test-support/` 下还有 loader smoke、LLM replay、会话快照等测试支撑包,它们是仓库自己的测试基础设施;`dsh-tools` 导出的 `defineContentToolFixture` 也标着 `@internal`,只用于仓库测试,产品工具应该声明自己的领域值。

## 踩坑

1. **在 `ToolDefinition` 上找"需要审批"的字段**——没有。用 `tools/pre-execute` 返回 `ask`,或 `ctx.tools.guard()` 拒绝
2. **执行体返回内容块或一段描述文字**——`execute` 只返回规范值,文字交给 `output.render`。否则 PTC 程序只能去解析文字
3. **HTTP 404、进程退出码非零就抛错**——那是领域结果,放进值里。只有基础设施失败才抛
4. **不把 `exec.signal` 传下去**——用户取消后工具还在跑,`timeoutMs` 也失效
5. **以为写了 `timeoutMs` 就有超时**——注册表不执行它,要组合里有 `dsh-tool-call-timeout-policy`
6. **以为参数里的 `default` 会自动填值**——它只是注解,可选参数仍可能是 `undefined`
7. **嵌套 object 没写 `additionalProperties`**——DSL 要求显式声明,编译时就会报错
8. **把并发安全当默认**——不返回 `true` 就是独占执行。真要并行,保证不修改父级持有的状态
9. **后台 job 用 `exec.signal` 控制生命周期**——id 发布后外层取消不会停止作业,要用任务自己的信号,通过 `cancel` 停止
10. **写了 `presentCall` 却在 Web 上看不到专门卡片**——内置 Web Client 不读它,要注册 `tool.call.toolview` 渲染器
