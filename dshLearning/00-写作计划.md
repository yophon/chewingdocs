# DeepSeek Harness 写作计划

> Claude Code 系列讲的是"把一个闭源 harness 用到顶"。DeepSeek Harness(`dsh`)是 DeepSeek 在 2026 年 8 月开源的 agent harness,MIT 协议,**连 agent loop 本身都是可替换的插件**,而且仓库把内部机制写得很细。这给了一个难得的机会:不光学怎么用,还能把一个真实在跑的 harness 从启动装配、主循环、工具管线到会话存储整个拆开来看。

---

## 时间基线

本系列按 **2026 年 10 月** 的状态编写:

- dsh `0.2.1-rc.2`(2026-10-17,commit `687f282e8`),仍是 developer preview。README 原话:"THERE WILL BE COMPATIBILITY-BREAKING CHANGES"
- 插件框架 Cordis `4.0.0-rc.7`,以 `@deepseek-ai/cordis` 的名字 vendored 在仓库里,带 24 处本地修改
- 默认模型:DeepSeek V4.1 Flash(`deepseek-flash`)和 V4 Pro(`deepseek-v4-pro`),上下文 1M
- 会话格式 v4 已定稿

光 0.2.1 这一个小版本就有 30 多份升级指南。**命令、配置字段、默认值以仓库 `docs/` 和对应包的 README 为准**,正文里的关键事实都要标出仓库路径,版本更新时可以逐条核对。

---

## 设计思路

dsh 和 Claude Code 最大的不同是开源,文档覆盖到每个子系统(`docs/subsystems/`)、Cordis 教程、cookbook 和持久化变更记录。所以本系列比 Claude Code 系列多出一整层"读懂内核"。

五层结构:

```
用 dsh → 读懂 dsh 内核 → 扩展 dsh → 多 Agent 与无人值守 → 选型与落地
```

- 第一层只讲用户看得到的东西,读完能在自己的项目里安全地用起来
- 第二层是本系列的重心:一个 harness 由哪些部件组成、怎么拼起来
- 第三层站在插件作者的角度:写工具、接模型、做分发
- 第四层讲子代理、workflow 脚本、定时任务,以及把 dsh 嵌进别的系统
- 第五层把 dsh 放回 harness 全景里比较,给出团队采用的基线

## 写作注意

调研和写作中发现的、容易写错的地方。dsh 更新后修订正文时,先过一遍这张清单:

- **"Agent = Model + Harness" 不是官方说法**,出自第三方文章,仓库里没有。官方定位是 "everything-is-a-plugin, powered by Cordis"
- **Cordis 出自 Koishi 生态**这一点仓库里没写,只有 LICENSE 里的 "Copyright (c) 2021-present Shigma"。要写的话另找一手来源
- **session log 默认上传是真的**:base bundle 默认把完整会话日志以 `dsh_session_log` 字段增量发给 `deepseek-official` 路由,内容可含 cwd、提示词、工具参数和结果。sdk-minimal 也挂了这一行;`deepseek-account` 路由文档没提,但源码里没有按路由过滤,按"大概率也会带"处理。关闭入口是 Web 的 Settings → General → Upload Session Log(只改当前 profile),或在 `$DSH_HOME/cordis.patch.yml` 把对应行的 `enabled` 设为 `false`。`DSH_TELEMETRY_*` 管不到它
- **approval policy 的 `never` 是自动拒绝**,不是自动批准。headless 和 SDK 没有审批应答方,`ask` 一律解析为 `unavailable` 被拒
- **PTC 的全称**:`docs/` 里没有展开,Web UI 预设帮助文案写作 Programmatic Tool Calling,正文以 UI 文案为准
- **Agent 预设在 0.2.1-rc.2 的设置页是只读的**,只能选默认、看 YAML;`web-app` README 里"可以编辑"的说法和其他文档不一致
- **HMR 默认不监视源码**:base 里 `hmr` 行是 `root: []`,只重载 profile 和 home 两层 patch,不管 `--patch` 叠加层
- **升级指南目录名是变更之前的版本**:`docs/upgrade-guide/v0.2.1-alpha.2/` 记录的是从 alpha.2 升到下一个版本的变化,正文写"vX 之后的版本",不写"从 vX 起"
- **默认模型 id 是 `deepseek-flash`**(DeepSeek-V4.1-Flash);acp bundle 和 Python 示例里的 `deepseek-v4-flash` 不在默认目录里
- **Ollama 没有官方文档**,能用的说法是"通过 Custom model API 接 OpenAI 兼容的自托管服务"
- **plan mode 只是软约束**,真正的边界在 sandbox 和 approval
- **hooks 桥的 matcher 匹配的是 dsh 的小写工具名**,Claude Code 里的 `Edit|Write` 不会命中;SKILL.md 必须写 `name`,不会退回用目录名
- **VitePress 会把正文和行内代码里的 <code v-pre>{{…}}</code> 当成 Vue 插值**,要显示原样时用 `<code v-pre>…</code>` 或放进代码块
- 实验性功能(agent team、worktree、webhook、hooks 桥、mods 桥、浏览器 / Computer Use)修订时都要重新核对当前版本
- 第 30 篇的 Codex CLI、OpenCode、Pi 信息来自 2026-10 的外部资料,修订时要重新查
