# 模型、凭证与网络

装好之后的第一件事是让 dsh 能调到模型。Claude Code 基本只面对 Anthropic 一家(外加 Bedrock、Vertex 这类托管渠道),dsh 则天生是多模型的:DeepSeek 走自带的原生适配器,其他几十家提供商走 pi-ai 的目录,公司网关和自建服务走"自定义模型 API"。这一篇讲怎么配、key 存在哪、多处都有 key 时谁说了算,以及怎么让它走代理。

> 一句话先记住:**DeepSeek 走原生适配器,其他模型走 pi-ai;key 存在 `$DSH_HOME/.credentials.yaml`,而且在 `v0.2.1-alpha.2` 之后的版本里,存储的 key 优先于你导出的环境变量**。headless 是例外,它默认只认环境变量。

---

## 一、心智:路由 + 模型 id

dsh 里一次模型请求由两部分决定:**路由**(provider id,比如 `deepseek-official`、`openai`、你自己起名的 `my-gateway`)和**模型 id**。路由由适配器插件注册到 `ctx.llm`,base bundle 默认挂了这三个适配器插件:

| 适配器 | 注册的路由 | 用途 |
| --- | --- | --- |
| `@deepseek-ai/dsh-llm-deepseek-api-key` | `deepseek-official` | DeepSeek 官方 API,用 API key |
| `@deepseek-ai/dsh-llm-deepseek-account` | `deepseek-account` | 登录 DeepSeek 账号后使用 |
| `@deepseek-ai/dsh-llm-pi-ai` | 你在设置里添加的每个提供商 | 第三方提供商、网关、自建服务 |

两个 DeepSeek 路由共用 `dsh-llm-deepseek` 这套传输层;pi-ai 一开始没有任何路由,你在 **设置 → 模型** 里每加一个提供商,它就注册一条。两类适配器可以同时挂,路由名不冲突。

几条通用规则:

- **改模型配置不用重启**,下一次请求就生效
- 在模型选择器里选中一个模型,它同时成为**新会话**的默认模型;已经发过请求的会话保留自己日志里记录的模型
- 适配器的线协议细节(Messages API、流式分片、dsh 自己的协议扩展)在 15 篇

## 二、DeepSeek 原生路由

### 2.1 API key 路由:`deepseek-official`

最短路径:打开 **设置 → 模型**,在 DeepSeek 卡片里填 API key 保存。key 只写不读,页面之后只拿到脱敏的描述;key 本身存进 `$DSH_HOME/.credentials.yaml`,设置里只保存一个凭证引用 `DEEPSEEK_API_KEY`。

也可以不进界面,直接导出环境变量:

```bash
export DEEPSEEK_API_KEY=sk-...
dsh web
```

这条路由的关键事实:

| 项目 | 值 |
| --- | --- |
| 协议 | DeepSeek 的 Anthropic 兼容 Messages API |
| 默认地址 | `https://api.deepseek.com/anthropic`;显式配置 `baseURL` > `$DEEPSEEK_BASE_URL` > 默认值 |
| 默认模型 | `deepseek-flash`(DeepSeek-V4.1-Flash,文本 + 图片)、`deepseek-v4-pro`(DeepSeek-V4-Pro,纯文本) |
| 上下文窗口 | 两个默认模型都是 1,000,000 token |
| 单次输出上限 | `maxTokens` 默认 256,000 |
| Web 默认选择 | `deepseek-official` / `deepseek-flash` |

模型 id 会原样传到线上,所以 DeepSeek 新出的模型不必等 dsh 更新目录;目录里没有的 id 按纯文本路由处理,但图形界面里只能选目录里有的条目。`read_image` 这类图片能力需要选支持图片的模型。

### 2.2 账号路由:`deepseek-account`

不想管 API key,可以登录 DeepSeek 账号:在 **设置 → 账号与余额** 点登录,然后在系统浏览器里完成授权。模型选择器里会多出一个 **DeepSeek 账号** 提供商。

| 行为 | 说明 |
| --- | --- |
| 模型列表 | 从账号服务的 `GET /models` 拉取,每个账号可以看到不同的模型;拉不到时用内置目录(`deepseek-flash`、`deepseek-v4-pro`) |
| 版本门槛 | 模型声明了最低 dsh 版本而你的版本不够时,请求在发出前失败,错误码 `CLIENT_UPGRADE_REQUIRED`,会写出需要的版本 |
| 未登录 | `ACCOUNT_SIGN_IN_REQUIRED`,模型列表为空 |
| 余额不足 | `ACCOUNT_QUOTA`,界面会给出充值入口 |
| 凭证 | 账号授权也存在本地凭证存储里;退出登录只删账号授权,不动 API key |

**两条路由互不兜底**:`deepseek-official` 只认它配置的 API key,`deepseek-account` 只认账号授权。账号路由没有模型编辑器,要调整单个模型的容量,在 profile patch 里用 `modelOverrides`:

```yaml
- id: llm-deepseek-account
  config:
    modelOverrides:
      deepseek-flash:
        contextWindow: 524288
        maxTokens: 131072
```

### 2.3 reasoning effort

DeepSeek 路由的每个模型都提供四档:`off`、`low`、`high`、`max`,默认 `high`。模型选择器里的 **推理等级** 菜单就是它。

- `low` / `high` / `max` 开启思考,作为 `output_config.effort` 发出
- `off` 发送 `thinking.type: disabled`
- 部署级的 `thinking: disabled` 会把所有请求锁死在 `off`,并在加载时拒绝其他档位

改默认档位:

```yaml
- id: llm-deepseek
  config:
    reasoningEffort: max
```

在选择器里选过一档后,它会和模型一起保存成新会话的默认值。

## 三、第三方提供商:pi-ai 目录

### 3.1 添加

**设置 → 模型 → 添加模型提供商**,卡片默认停在 **第三方模型提供商**。下拉里是 dsh 安装时自带的 pi-ai 目录,列的是提供商 id。按 `packages/llm/llm-pi-ai/src/provider-data.generated.ts`,0.2.1-rc.2 里有四十多个,节选:

| provider id | 说明 | 目录里的环境变量 |
| --- | --- | --- |
| `anthropic` | Claude | `ANTHROPIC_API_KEY` 等 |
| `openai` | OpenAI | `OPENAI_API_KEY` |
| `moonshotai` / `moonshotai-cn` | Kimi | `MOONSHOT_API_KEY` |
| `zai` / `zai-coding-cn` | GLM | `ZAI_API_KEY` / `ZAI_CODING_CN_API_KEY` |
| `google` | Gemini | `GEMINI_API_KEY` |
| `openrouter` | OpenRouter | `OPENROUTER_API_KEY` |
| `azure` | Azure OpenAI | `AZURE_OPENAI_API_KEY` |
| `amazon-bedrock` | Bedrock | AWS 凭证链 |
| `deepseek` | pi-ai 目录里的 DeepSeek 条目(端点 `https://api.deepseek.com`),和原生路由是两回事 | `DEEPSEEK_API_KEY` |

选好后填 key 保存即可,端点、协议和模型列表都来自目录。这个列表跟着 pi-ai 版本变,以你安装版本的 Models 页面为准。比如 `v0.2.1-alpha.2` 之后的版本就把 Azure 的路由名从 `azure-openai-responses` 改成了 `azure`,旧配置不再解析。

### 3.2 认证提示与登录

key 输入框旁的 **?** 解释凭证优先级。留空表示使用已保存的凭证,或者尝试目录列出的环境变量:绿色提示表示检测到了环境变量,黄色表示没检测到。**检测只看变量在不在,不验证 key 是否有效**;AWS profile、Google ADC 这类提供商自己管理的凭证文件不在检测范围内。

部分提供商在 pi-ai 里自带登录流程(OAuth 或交互式输入 key),登录结果存进凭证存储,记录名是 `llm-pi-ai/<provider id>`,刷新时有跨进程锁。两个例外要知道:

- `openai` 的 "Sign in with ChatGPT" **不提供**,因为它要求一个 dsh 不保存的设备 id,这条路由用 API key
- `openai-codex` 这类没有原生 key 认证的提供商,页面上不显示 key 输入框

## 四、自定义模型 API

### 4.1 什么时候用

中转站、公司网关、自建推理服务,或者目录里没有的提供商:把卡片切到 **自定义模型 API**,填小写的 Provider ID、基础 URL、API 协议、凭据和至少一个模型。

| 界面选项 | 写进 patch 的 `api` 值 |
| --- | --- |
| OpenAI Chat Completions | `openai-completions` |
| OpenAI Responses | `openai-responses` |
| Anthropic Messages | `anthropic-messages` |

- **一个提供商只说一种协议**,同时提供两种协议的网关要建两个提供商
- **Provider ID 不能改**,请求、会话、默认模型和凭证引用都用它;要改名只能新建一个再删旧的。显示名、地址、协议、凭证和模型都能改
- 配置存在当前 profile 的 `cordis.patch.yml` 里

### 4.2 获取可用模型

**模型目录 → 获取可用模型** 会用表单里当前的地址、协议和 key 去问端点:OpenAI 两种协议请求 `GET {baseURL}/models`,Anthropic Messages 用原生的 `GET /v1/models`。勾选后 **添加所选**,保存前什么都不写。

它是便利功能,不是保证:端点不支持或返回格式读不懂时,手动填模型 id 照样能用。另外,**内置提供商永远从安装目录回答**,就算你把它的地址指向网关;想看网关真实提供什么,建一个自定义提供商去拉。

### 4.3 自建服务与 Ollama

仓库里**没有任何 Ollama 的文档或示例**。能确定的说法是:通过自定义模型 API,用 `openai-completions` 协议接 OpenAI 兼容的自托管服务。手写成 patch 大致如下:

```yaml
- id: llm-pi-ai
  config:
    providers:
      local-llm:
        displayName: Local LLM
        apiKeyEnv: LOCAL_LLM_API_KEY
        api: openai-completions
        baseURL: http://127.0.0.1:8000/v1
        compat:
          supportsDeveloperRole: false
          maxTokensField: max_tokens
        models:
          - id: my-local-model
            contextWindow: 131072
```

- 目录外的路由必须同时有 `api`、`baseURL` 和非空的 `models`
- 本地服务不校验 key 时,仓库没有说明能否省略凭据;稳妥做法是给 `LOCAL_LLM_API_KEY` 一个占位值
- 自托管 Chat Completions 还有 `thinkingTokenBudgetField`、`vllmPriority` 两个可选开关
- 回环地址永远不走代理(见第六节)

### 4.4 网关拒绝所有请求时

pi-ai 根据 URL 决定请求长什么样,认不出的地址一律按 OpenAI 本家处理,而大多数"OpenAI 兼容"网关至少有一处不兼容。最常见的两个:推理模型的 system prompt 以 `role: "developer"` 发出,以及输出上限用 `max_completion_tokens`。上面例子里的两个 `compat` 开关就是修这个的。

reasoning 等级也要自己声明:手动添加的模型默认没有等级,选择器里不出现推理菜单。在模型选项里打开 **推理等级**,或写 `reasoningEfforts`。DeepSeek V4 放在 OpenAI 兼容网关后面时,还需要 `compat.thinkingFormat: deepseek`,否则 `off` 关不掉思考。

### 4.5 界面之外的高级字段

推理等级(内置提供商的)、请求兼容开关、`headers`、`timeoutMs`、`retryPolicy` 这些界面上没有,写在 `$DSH_HOME/profiles/<profile>/cordis.patch.yml` 里。`dsh web` 时 `<profile>` 就是 `web`。浏览器和服务在同一台机器上时,设置页顶部的 **打开配置文件** 能直接打开它;适配器下次请求时重新读取,不用重启。

**注意 patch 的语义是整行替换**:对 `llm-pi-ai` 这一行写 `config`,会替换掉整个 `config`,包括其他提供商。改的时候在现有条目上改,别另起一个只写了一个字段的同 id 条目。叠加规则见 11 篇。

## 五、凭证:存在哪、谁优先

### 5.1 凭证文件

```yaml
version: 1

refs:
  DEEPSEEK_API_KEY: sk-…
  OPENAI_API_KEY: sk-…

records:
  llm-pi-ai/openai-codex:
    kind: grant
    payload: { … }
```

- `refs` 按环境变量名存 key 值;`records` 按 `<owner>/<id>` 存插件自己的凭证(OAuth 授权、AWS profile 等)
- 可以直接编辑,文件变化会自动重新加载;删掉一行就等于删掉那个 key
- POSIX 上文件权限必须只有你自己可读,否则拒绝加载并提示 `chmod 600`;Windows 跳过这项检查
- **这不是隔离边界**:agent 的工具进程以你的用户身份运行,读这个文件和读你别的文件一样容易。dsh 只是不把路径告诉 agent、不把内容放进环境变量

### 5.2 优先级

Web、SDK、ACP 三类 profile 挂载了凭证存储,查找顺序是:

| 顺序 | 位置 | 能被页面写入 |
| --- | --- | --- |
| 1 | `$DSH_HOME/.credentials.yaml` | 是 |
| 2 | 启动 dsh 时的环境变量 | 否 |
| 3 | 启动目录的 `.env` | 否 |
| 4 | `$DSH_HOME/.env` | 否 |

这个顺序是 `v0.2.1-alpha.2` 之后改的(升级指南按变更前的版本归档):以前导出的环境变量优先,导出期间 Models 页面甚至没法为同名 key 保存值。现在**存储的值优先**,环境变量只在文件里没有这个名字时生效。仓库里 `apps/cli/reference/README.md` 的 "Shared deployment behavior" 一节还写着旧顺序,以 `credentials-local` 的 README、源码和升级指南为准。

实际后果:

- CI 或容器挂载了一个已经存过 key 的 home,又用 `-e` 传了同名变量,**用的是文件里的旧 key**。想让环境变量生效,删掉 `refs` 下那一行(运行中的进程会自动重新读取)
- 环境变量层是启动时的快照,启动后再 `export` 看不到,要重启

### 5.3 headless 默认不读存储

随附的 `headless` profile 禁用了凭证存储、授权流程和 DeepSeek 账号三行,只按"启动环境 → 项目 `.env` → home `.env`"取 key,不碰 `.credentials.yaml`。Web 里保存的 key 和账号登录**默认对 headless 无效**。确实要用,在 `$DSH_HOME/profiles/headless/cordis.patch.yml` 或 `--patch` 里恢复:

```yaml
- id: credentials
  disabled: false
- id: authorization
  disabled: false
- id: deepseek-account
  disabled: false
```

恢复后也恢复了"存储优先"。另外,导出一个空值会遮住 `.env` 里的同名值,要用 `.env` 就 `unset` 掉。

## 六、网络与代理

dsh 的出站请求(模型调用、网页搜索、网页抓取、HTTP 方式的 MCP server)走标准代理环境变量,启动时读取:

```bash
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
export NO_PROXY=internal.example.com,.corp.example.com
```

规则和限制:

| 项目 | 行为 |
| --- | --- |
| 写在哪 | shell 里导出,或写进 `$DSH_HOME/.env`;导出的优先 |
| 项目 `.env` | **不能**设代理,写了会拒绝启动,防止克隆下来的仓库决定你的流量去向 |
| 系统代理设置 | 不读。Clash 之类的"系统代理"开关浏览器能用、命令行看不到;要么导出变量,要么用 TUN 模式 |
| `NO_PROXY` | 按主机名和后缀匹配,**不支持 CIDR**(`10.0.0.0/8` 无效);回环地址自动直连 |
| SOCKS | 不支持,`socks5://` 会在启动时报告并跳过,那个协议改为直连 |
| `ALL_PROXY` | 只设它也行,两种协议都会回退到它 |
| 企业 TLS 拦截 | 启动前导出 `NODE_EXTRA_CA_CERTS=/path/to/corporate-ca.pem` |

两个容易忽略的点:

- **dsh 启动的子进程继承这些变量**:bash 工具里的命令、`git`、`gh`、子进程 MCP server 都会用。代理 URL 里带密码的话,模型写的命令也能读到它
- **有些请求始终直连**:本机回环;模型写的代码(workflow worker、PTC 运行时进程拿不到代理设置);OTLP 遥测导出;`web_fetch` 指向私有地址时直接拒绝

验证是否生效:

```bash
dsh headless "fetch https://example.com and tell me the page title"
```

然后看代理软件的连接日志。

## 踩坑

1. **导出了新 key 但请求还在用旧的**——`v0.2.1-alpha.2` 之后的版本里 `.credentials.yaml` 里的值优先。删掉 `refs` 下同名的那一行,或者在页面上更新
2. **Web 里配好了,`dsh headless` 却报 `MISSING_CREDENTIAL`**——headless 默认不读凭证存储。导出环境变量,或用三行 patch 恢复存储
3. **登录了账号,`deepseek-official` 还是报缺 key**——两条路由互不兜底,账号对应的是 `deepseek-account`,在选择器里选 **DeepSeek 账号** 下的模型
4. **在 patch 里只写了一个字段,其他提供商全没了**——patch 整行替换 `config`,在现有条目上改
5. **想改自定义提供商的 Provider ID**——不能改,新建一个再删旧的
6. **网关 key 和地址都对,但每个请求都被拒**——先在路由上加 `compat.supportsDeveloperRole: false` 和 `compat.maxTokensField: max_tokens`
7. **手动加的模型没有推理菜单,或 `off` 关不掉 DeepSeek 的思考**——声明 `reasoningEfforts`;OpenAI 兼容网关后面的 DeepSeek 还要 `compat.thinkingFormat: deepseek`
8. **把 `10.0.0.0/8` 抄进 `NO_PROXY`**——不支持 CIDR,改写主机名或域名后缀
9. **在项目 `.env` 里写代理**——会拒绝启动,改写到 `$DSH_HOME/.env` 或 shell 里
10. **以为 `chmod 600` 就能防 agent 读 key**——agent 以你的身份运行,文件权限挡不住它。需要隔离 key 的部署要换别的方案(31 篇)
