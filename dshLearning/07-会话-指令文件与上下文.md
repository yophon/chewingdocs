# 会话、指令文件与上下文

前几篇解决了"装好、选模型、选预设、定边界"。这一篇回到日常使用:**会话存在哪、怎么找回来、怎么分叉和导出,模型每次开工前读了哪些指令文件,上下文满了怎么办**。

对照 Claude Code 系列,这一篇大致覆盖那边 05 篇(会话与上下文)和 06 篇(CLAUDE.md)的范围,但只讲用户看得到的部分。会话日志的内部结构见 17 篇,压缩的机制和 KV Cache 纪律见 16 篇。

> 一句话先记住:**dsh 的会话是一份 append-only 的事件日志,按项目目录存在 `$DSH_HOME/sessions` 下;指令文件只认 `AGENTS.md` / `CLAUDE.md` 及其 `.local` 版本,作为一条普通消息追加进历史,而不是写进 system prompt**。

## 一、会话存在哪

### 1.1 磁盘布局

base bundle 把会话持久化的根目录设为 `$DSH_HOME/sessions`(默认 `~/.dsh/sessions`):

```text
~/.dsh/sessions/
  --<规范化后的 cwd>--/            # 按项目目录分组;没有 cwd 的会话放 _no-cwd/
    <编码后的会话 id>/
      session.v4.jsonl.zstd        # 当前格式(v4),Zstandard 压缩
      session.v3.jsonl.zstd        # 升级前的旧格式代际,不可变地保留
```

几个要点:

- **每个会话一个目录**,文件名里的 `vN` 是会话格式版本。当前写入格式是 v4;旧版本的文件迁移后原样保留,运行时总是选编号最高的那一代
- **默认压缩**:每批事件是一个带校验的 Zstandard 帧。想直接用文本工具看,可以把 `session-persistence-jsonl` 行的 `compression` 改成 `'none'`;已有会话导出见 1.4 节
- **懒创建**:新建但从没发过消息的会话不落盘
- **崩溃安全**:每批追加后 `fsync`;崩溃时中断的最后一轮保留下来,恢复时补上合成的收尾事件,已提交的事件从不改写

和 Claude Code 把会话存成 `~/.claude/projects/.../*.jsonl` 的思路相近,区别是 dsh 默认压缩,而且格式有版本号和迁移流程(17 篇)。

### 1.2 Workspace:Web 里的项目分组

Web 侧栏的 **Workspace** 是"你在哪些目录工作"的持久记录:一个目录对应一个 Workspace,下面挂着属于它的会话。它不是会话本身的一部分,模型看不到它。

- **Add workspace** 选一个目录,注册并打开新会话
- View options → Group by 可以选 **WorkSpace**(平铺)或 **Workspace Tree**(按已注册的父目录嵌套)
- **删除 Workspace 不会删除会话**,它们会出现在 Ungrouped 下

### 1.3 会话的日常操作

| 操作 | 怎么做 | 说明 |
| --- | --- | --- |
| 恢复 | 侧栏点开 | 进程重启后照样能打开;权限预设、plan mode 状态都从日志恢复 |
| 重命名 | 行菜单 Rename,或双击标题 | 标题默认由模型根据第一条提示自动生成;确认重命名(哪怕不改字)会锁定标题,不再自动重生成 |
| 置顶 | 行菜单 Pin | 置顶会话排在普通会话前面 |
| Fork | 行菜单 Fork | 从源会话**最后一个完成的轮次**分叉,标题自动加序号 |
| 从某一轮分叉 | 轮次末尾消息操作栏里的 branch 按钮 | 在那一轮结束处分叉并打开子会话 |
| 归档 | 行菜单 Archive | 有运行中的工作(当前轮、子代理、后台 job、定时提醒)时会先列出来,确认后停掉再归档;可撤销 |
| 复制 id | 行菜单 Copy Session ID | 给 headless `--session-id` 等场景用 |

归档的会话默认隐藏,View options 里可以切到"显示归档"或"只看归档";归档会话不能直接打开,要先 Unarchive。仓库文档里**没有删除会话的入口**,Web 侧栏只有归档。

会话行上的警告点表示有待处理的交互:**Approval**(等审批)、**Plan review**(等审阅计划)、**Answer**(等回答问题)。子代理产生的会话不在侧栏显示。

### 1.4 搜索、Trajectory 与导出

**搜索**。Desktop 默认快捷键是 Mod+K(Windows / macOS 的 Web 用平台默认绑定,Linux Web 默认不绑定)。默认只匹配**会话标题和 Workspace 名称**的子串,不区分大小写,最多 20 条结果。

全文搜索默认关闭:base 和 web-app bundle 都把 `session-query-sqlite` 的 `openAt` 设成 `never`。想搜会话内容,在 patch 里打开:

```yaml
- id: session-query-sqlite
  config:
    path: ':memory:'        # 也可以换成持久化路径
    openAt: first-search    # 第一次搜索时才加载 SQLite
```

打开后结果里会多出按相关度排序的内容匹配和片段。它基于 SQLite FTS5,**按 token 和短语字面匹配**:查询会被当作一个字面短语,`OR`、`*`、引号都按普通字符处理;不做模糊匹配,也不匹配词内部的任意子串(`AI` 搜不到 `BRAID`)。

**Trajectory**。会话视图里的 Trajectory 标签页把会话展示成按轮次组织的账本和时间线:User、Assistant、Tool、子工具调用和压缩记录分组排列,点开任一条能看到 token 用量、耗时、输入、输出和图片。`run_code` 的调用会显示程序描述和带行号的源码。排查"模型到底看到了什么、哪一步慢"时比聊天视图直接得多。

**导出**。会话头部的更多菜单里选 **Download session log**,或在输入框输入 `/export`,浏览器会下载 `dsh-session-<id>.zip`,里面是这个会话、它的子会话和附件。

### 1.5 评价与反馈

- 每轮最后一条助手消息的操作栏里有赞 / 踩,两者都会打开对话框,可选 7 个类别之一并写备注;再点一次已选中的评价是撤回
- `/feedback <文字>` 直接记录一条会话级反馈,回显会话 id 和匿名用户 id;不带文字的 `/feedback` 在 Web 里打开同一个对话框

这些都是只写日志的事件,**不进模型上下文,也不打断正在运行的任务**。但在默认的 `FEEDBACK_ONLY` 遥测模式下,每次反馈都会触发一次会话前缀上报,见 06 篇。

### 1.6 在别的入口接着跑

| 入口 | 怎么恢复 | 限制 |
| --- | --- | --- |
| headless | `dsh --profile headless --session-id <id> "继续"` | 工作目录必须和会话记录的一致;不接受子代理会话和 fork 出来的会话;会话的 agent 预设必须在当前 profile 里存在;id 不存在直接报错 |
| ACP | `session/list` + `session/resume` | 不支持 fork、删除、`session/load` |
| SDK | 调用时传 `session_id` | 细节见 27 篇 |

headless 每次默认新建 `session-<uuid>`,用 `--json` 时开头的 `session` 事件会给出这个 id。

## 二、工作目录

### 2.1 创建时定下,运行中可切换

会话创建时把工作目录记进不可变的会话头:CLI 下是启动 `dsh` 的目录,Web 下是所选 Workspace 的目录。之后模型可以用 `working_directory` 工具(唯一参数 `cd`)切换当前目录:

| 受切换影响 | 不受切换影响 |
| --- | --- |
| 相对路径的文件操作 | 沙箱的可写根目录(仍锚定原始项目,05 篇) |
| 新启动的进程 | 已经打开的终端和持久 shell |
| 指令文件发现、skill 发现、文件补全 | 会话属于哪个 Workspace |

切换只对当前会话生效;当前目录如果被删除,会自动回到原始项目目录。每次切换都会作为一条用户上下文告诉模型,不改 system prompt。

### 2.2 bash 里的 `cd` 不算

bash 工具每次调用都是一个新的 `bash -c`,`cd` 不会延续到下一次调用,工具描述也要求模型用 `workdir` 参数而不是 `cd`。真正改变会话工作目录的只有 `working_directory`。

## 三、AGENTS.md 与 CLAUDE.md

### 3.1 加载链

base 默认挂了 `@deepseek-ai/dsh-agent-instructions`。第一次请求前,它按从宽到窄的顺序收集:

```text
1. $DSH_HOME/AGENTS.md                (默认 ~/.dsh/AGENTS.md)
2. ~/.agents/AGENTS.md                ($DSH_AGENTS_HOME 可改位置)
3. 项目链:从项目根到会话工作目录,每一层依次读
   AGENTS.md → CLAUDE.md → AGENTS.local.md → CLAUDE.local.md
```

- **项目根**是向上找到的第一个含 `.git` 的目录;一直找不到就只用工作目录本身
- **去重按内容**:同一层里 `CLAUDE.md` 和 `AGENTS.md` 去掉首尾空白后完全相同,只渲染一次;两个全局文件之间也一样。内容不同就**两份都加载**
- **`.local.md` 是叠加层**,在同层的基础文件之后加载;两个全局位置没有 `.local` 版本

### 3.2 预算

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `maxBytes` | `65536`(base 设定) | 整条渲染后消息的字节上限 |
| `maxSourceBytes` | `1048576` | 单个源文件的上限 |
| `projectRootMarkers` | `['.git']` | 标记项目根的目录名 |

超预算时**先整份丢掉更宽泛的文件,最后才截断最具体的那份**,并在消息里写明 `Workspace instruction budget ...`,列出被省略和截断的路径。想放宽:

```yaml
- id: agent-instructions
  config:
    maxBytes: 131072
```

### 3.3 它以什么形式进入上下文

指令文件**不写进 system prompt**,而是作为一条普通的 `user/message` 追加在历史里,外面包一层 `<system-reminder>`,开头写明"更具体的指令优先,且不覆盖系统、开发者和用户的直接指令"。这样做是为了不破坏请求前缀的缓存(16 篇),代价是它和其他历史一样会被压缩。

### 3.4 刷新:靠文件操作触发,不监听

- 模型用 `read` / `write` / `edit` 成功访问了更深的目录,下一次请求就会追加那个目录新适用的指令文件(`Additional instructions from: ...`)
- 已加载的文件变了,下次访问时追加 `Updated instructions from: ...`;文件消失则追加 `Instructions removed: ...`
- 会话工作目录切换后,项目链在下一次请求前重新加载;恢复会话时也会对账一次
- **没有文件监听**:你在编辑器里改了 AGENTS.md,要等模型下次用文件工具访问相关路径才会生效。bash 里 `cd` 进子目录也不会触发发现

### 3.5 和 Claude Code 的差异

| 能力 | Claude Code | dsh |
| --- | --- | --- |
| 全局指令 | `~/.claude/CLAUDE.md` | `$DSH_HOME/AGENTS.md`、`~/.agents/AGENTS.md`,**不读 `~/.claude/CLAUDE.md`** |
| 项目文件名 | `CLAUDE.md`、`CLAUDE.local.md` 等 | `AGENTS.md`、`CLAUDE.md` 及两者的 `.local.md` |
| `@path` 导入 | 支持 | **不解析** |
| `.claude/rules/` | 支持 | **不解析** |
| 小写文件名 | — | 不认 |

只想让 dsh 读现有的 CLAUDE.md,直接用就行;依赖 `@` 导入或 rules 目录的内容要摊平到文件里。完整的迁移讨论见 23 篇。`sdk-minimal` 不挂指令发现。

## 四、上下文满了:`/compact`

### 4.1 自动压缩

base 默认挂了 `dsh-compaction-basic`。对上下文窗口 `W`、输出上限 `O`,默认在 `floor(min(W × 0.8, W − O − 65536))` 个 token 时触发:把最旧的一段历史换成一条摘要,保留最近的一部分原文。服务商确认上下文超长时,也会压缩一次再重试。阈值怎么算、怎么按模型调,见 16 篇。

### 4.2 手动 `/compact`

| 输入 | 结果 |
| --- | --- |
| `/compact` | 即使没到阈值,也压缩一段较旧的历史,报告被替换的条目数和估算节省的 token |
| 没有可压缩的历史 | `No compactable history yet.` |
| `/compact 任何参数` | `Usage: /compact (no arguments)` |

和 Claude Code 的 `/compact <关注点>` 不同,**dsh 的 `/compact` 不接受参数**,不能指定摘要侧重什么。另外:

- agent 正在跑或另一个压缩还没结束时,会提示暂不可用
- 压缩期间你发的消息会排队,压缩完成后再开始
- 压缩不消耗一个模型轮次

### 4.3 压缩不删日志

会话日志是 append-only 的:压缩只是追加一条摘要,并让后续请求"看不到"被替换的那段,原始事件仍在日志里。Trajectory 里能看到压缩记录,`/export` 导出的也是完整日志。这也意味着 session log 上传(06 篇)发出去的是完整事件,不是压缩后的视图。日志与"模型可见视图"的关系见 17 篇。

## 踩坑

1. **在 `~/.claude/CLAUDE.md` 里写了全局约定,dsh 没反应**——dsh 只读 `$DSH_HOME/AGENTS.md` 和 `~/.agents/AGENTS.md`
2. **CLAUDE.md 里用 `@docs/style.md` 导入**——不解析,模型只会看到字面的 `@docs/style.md`
3. **改了 AGENTS.md 立刻提问,模型还按旧的来**——没有文件监听,要等文件工具访问到相关路径,或新开会话
4. **AGENTS.md 和 CLAUDE.md 内容略有出入,上下文里出现两份**——去重只认完全相同的内容。保留一份,另一份删掉或做成完全一致
5. **指令文件很多,模型却没看到根目录那份**——超过 64 KiB 预算时先丢宽泛的文件。看消息里的 `Workspace instruction budget` 提示,或调大 `maxBytes`
6. **侧栏搜不到会话内容**——全文搜索默认关闭,只匹配标题和 Workspace 名称。按 1.4 节打开 `openAt`
7. **想用 `/compact 保留数据库相关讨论` 控制摘要**——不接受参数,会直接报用法错误
8. **用 headless `--session-id` 接着跑 Web 里 fork 出来的会话,被拒**——headless 不接受 fork 和子代理会话,工作目录也必须一致
9. **以为删了 Workspace 会话就没了**——会话还在 Ungrouped 下,磁盘上的日志也还在
10. **让模型 `cd` 到子目录工作,子目录的 AGENTS.md 没加载**——bash 的 `cd` 不改会话目录也不触发发现。用 `working_directory`,或让模型用文件工具读那里的文件
