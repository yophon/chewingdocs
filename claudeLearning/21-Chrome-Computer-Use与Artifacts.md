# Chrome、Computer Use 与 Artifacts

Claude Code 的核心能力是读写文件、跑命令。但有些事光靠终端做不到:**看网页真实渲染成什么样、操作一个只有图形界面的应用、把结果做成一个可以点、可以分享的页面**。这一篇讲三个补上这些短板的功能:用你的浏览器做事的 Claude in Chrome、控制屏幕的 computer use,以及把会话产出发布成网页的 artifacts。

> 一句话先记住:**Claude 会优先用最精确的工具**。有 MCP 或 connector 就用它,能用 shell 就用 shell,浏览器任务用 Chrome,实在没有别的办法才控制屏幕。你装这些功能,是给它"兜底的手",不是让它什么都去点界面。

---

## 一、Claude in Chrome

### 1.1 它能做什么

通过 Claude in Chrome 浏览器扩展,Claude Code 可以在你的浏览器里开标签页、操作页面,**共享你浏览器的登录状态**——你已经登录的网站它都能访问。操作在一个可见的 Chrome 窗口里实时进行,遇到登录页或验证码会停下来等你。

| 场景 | 例子 |
| --- | --- |
| 现场调试 | 读控制台报错和 DOM 状态,然后去修导致问题的代码 |
| 设计核对 | 照着设计稿写完 UI,打开浏览器确认是否一致 |
| Web 应用测试 | 测表单校验、查视觉回归、走一遍用户流程 |
| 已登录的应用 | 不需要 API connector 就能操作 Google Docs、Gmail、Notion |
| 数据提取 | 从网页上抓结构化信息存到本地 |
| 重复性浏览器任务 | 录入数据、填表单、跨多个网站的流程 |
| 文件上传 | 把本机文件传到网页的上传框 |
| 录制 | 把浏览器操作录成 GIF |

支持 Chrome、Edge,以及 Brave、Arc、Vivaldi、Opera 等 Chromium 内核浏览器。

### 1.2 开始使用

前提:安装 Claude in Chrome 扩展,**用 claude.ai 账号 `/login` 登录**(API key 或 `setup-token` 生成的长期令牌不行),第三方云服务商不支持。

```bash
claude --chrome
```

想每次都自动连接,在会话里跑 `/chrome`,选 **Enabled by default**。注意:默认开启会让浏览器工具和说明一直占着上下文,不常用的话按需开启更省。

然后直接让它用浏览器:

```
我刚改了登录表单的校验。打开 localhost:3000,用非法数据提交表单,
看看错误提示是否正确显示。
```

```
打开页面,看控制台里有没有和 checkout 相关的报错
```

看控制台时**告诉它要找什么模式**,别让它把所有日志都拉回来——日志往往很长。

### 1.3 权限

- **站点级权限继承自扩展本身**:在扩展设置里控制 Claude 可以在哪些网站上浏览、点击、输入
- auto mode 下,可能把页面内容、cookie、凭证发到别的源的浏览器操作会被分类器拦截;导航到可信内部域名、localhost、你点名的网址是放行的
- plan mode 下,录 GIF、开新标签页、执行快捷操作前会询问
- Claude 为任务开的标签页会归到一个和会话绑定的标签组里,`/clear` 时这组标签会被关掉

### 1.4 Chrome 扩展 vs Desktop 内置浏览器

| | Chrome 扩展 | Desktop 内置浏览器 |
| --- | --- | --- |
| 登录状态 | **你的**浏览器,有你所有的登录 | 干净的独立配置,没有登录 |
| 适合 | 需要你身份的操作:已登录的 SaaS、内部系统 | 构建和测试你的应用、不需要身份的网站 |

## 二、Computer use:控制屏幕

### 2.1 它解决什么

需要图形界面才能做的事——本来得离开终端自己动手的那些:

- **构建并验证原生应用**:写一个 macOS 菜单栏应用,编译、启动、把每个控件点一遍,确认能用了再交给你
- **端到端 UI 测试**:"测一下这个 Electron 应用的引导流程",它打开应用、点完注册、每一步截图。不需要配 Playwright
- **调试视觉和布局问题**:"弹窗在小窗口下被裁掉了",它缩小窗口复现、截图、改 CSS、再验证
- **操作只有图形界面的工具**:设计工具、硬件控制面板、iOS 模拟器、没有 CLI 也没有 API 的专有软件

### 2.2 CLI 里开启

研究预览,**CLI 里只支持 macOS**,需要 Pro 或 Max 计划,Team / Enterprise 不可用;需要交互式会话,`-p` 里不可用。

```
/mcp
```

在列表里找到内置的 `computer-use` server,选 **Enable**(按项目保存)。第一次使用时 macOS 会要求授予两项权限:

- **辅助功能**:点击、输入、滚动
- **屏幕录制**:看到屏幕内容

授权后可能需要重启 Claude Code。然后:

```
构建应用,启动它,把每个标签页点一遍确认没有崩溃。遇到错误状态就截图。
```

Desktop App 上 macOS 和 Windows 都支持,而且 macOS 上能在后台运行(20 篇)。

### 2.3 风险

computer use 运行在你**真实的桌面**上,能接触到你批准的一切。Claude 会检查每个动作、标记屏幕上可能的提示注入内容,但这不是沙箱。几条建议:

- 只给任务需要的应用授权
- 敏感窗口(密码管理器、网银、私人聊天)在它工作时关掉或最小化
- 涉及付款、删除、发送消息的操作,要求它停下来让你确认

## 三、Artifacts:把产出发布成一个网页

### 3.1 什么时候用

当**终端文本是错误的媒介**时:

- 带行内注释的 diff,带着评审者走一遍 PR
- 用会话里已经拉到的数据渲染一个仪表盘
- 把几种设计或实现方案并排对比
- 一个随着长任务推进不断更新的调查时间线
- 发给同事一个链接,而不是往 Slack 里贴一大段输出
- 一个每次打开都通过 MCP connectors 拉取最新数据的状态看板

artifact 是一个发布到 claude.ai 私有地址上的**可交互网页**。它**不是**一个带后端的网站:没有后端、单页、不能处理多个路由。需要后端的内部工具,部署到你自己的基础设施上。

### 3.2 创建和更新

```
做一个 artifact,带着行内注释的 diff 讲解这个 PR。
做一个上周部署失败按服务分布的仪表盘 artifact,调查过程中持续更新它。
```

Claude 可能在输出适合做成页面时主动发布,也可以你明确要求。没指定位置时,它把页面写成一个临时目录里的 HTML 或 Markdown 文件再发布。首次发布后会打印链接并打开浏览器:

- `Ctrl+]` 随时重新打开本会话最新的 artifact
- 输入框下方的 `⧉` 标记显示本会话的 artifact
- `/artifacts` 列出你拥有的和别人分享给你的 artifact,按 `o` 打开、`c` 复制链接、`d` 删除

更新:"在汇总图下面加一个按地区的拆分,重新发布"——Claude 改文件、重新发布到**同一个链接**,打开着的人看到的页面会原地更新。每次发布都是一个版本,可以在页面的分享控件里选择对外展示哪个版本。**换了会话想更新,把链接给 Claude**,否则它会新建一个。

### 3.3 分享与协作

- **新 artifact 只有你能看**
- **组织内分享**(Team / Enterprise):指定人或全组织,需要用组织账号登录查看
- **公开分享**:任何人都能打开,不需要登录;Team / Enterprise 需要 Owner 先开启
- **编辑者**:Team / Enterprise 可以把同事设为编辑者,他们通过 Claude 发布新版本;两边同时改时,Claude 会把自己的改动合并到更新的版本上再发布
- **评论**:组织内分享时,查看者可以在页面上评论;有编辑权的人可以把评论"发给 Claude",你的会话会收到并可以回复或处理。你也可以直接说"读一下这个 artifact 上的评论,按评论改"

### 3.4 实时数据:connector 驱动的页面

```
做一个我们未合并 PR 的仪表盘 artifact,页面加载时通过我的 GitHub connector 拉取实时列表。
```

关键点:**connector 调用用的是"正在看页面的人"的账号,不是发布者的**。所以同一个仪表盘,两个人看到的数据可能不同;每个查看者第一次调用前都要授权;页面上的按钮如果会触发有副作用的操作(发消息、改 issue),也是以点击者的身份执行。打算分享这类页面时,让 Claude 在每个实时区块里加一句"需要连接 XX connector"的提示。

### 3.5 模板:幻灯片、设计稿、文档

```
/slides 平台团队本季度可靠性工作回顾,给工程全员会用
/design 一个手机银行 App 的设置页面
```

- **`/slides`**:生成一个 Claude Slides 幻灯片,在浏览器里编辑和演示,可以下载成 .pptx 或 PDF
- **`/design`**:把 UI、页面流程、落地页、海报画成一张画布上的多个画板,可以直接选中元素修改,导出 PNG / PDF
- **Claude Docs**:以 claude.ai connector 的形式接入,要"写一份文档给团队看"时会用它。属于代码库的文档(比如 README)仍然是仓库里的文件

### 3.6 页面限制

| 限制 | 影响 |
| --- | --- |
| 外部请求 | 只能从 Google Fonts 加载字体,从少数几个公共 CDN(cdnjs、unpkg、Tailwind、jQuery、jsDelivr 部分路径)加载脚本 |
| 没有后端 | 是静态页面,不能自己验证查看者身份 |
| 下载 | 页面不能自己触发下载,需要声明下载能力 |
| 单页 | 相对链接无效,多部分内容用页内锚点 |

### 3.7 什么时候它会先问你

你亲自输入的 prompt 触发的新 artifact 直接发布,不弹窗。以下情况会先问:plan mode 下首次发布、页面要声明 connector 调用或文件下载等运行时能力、修改已经公开分享的 artifact、由会话内定时任务触发的发布、需要读取未授权的文件。

组织可以开关 artifacts、控制 connector 调用和公开分享、设置保留期限、查看审计日志。

## 四、三者的分工

| 需求 | 用 |
| --- | --- |
| 验证你的 Web 应用的真实表现 | Chrome(或 Desktop 内置浏览器) |
| 操作你已登录的网站 | Chrome |
| 测原生应用、模拟器、只有图形界面的工具 | Computer use |
| 把分析结果、方案对比、看板给人看 | Artifact |
| 做一份要演示的幻灯片或设计稿 | `/slides`、`/design` |

## 五、踩坑

1. **用 API key 登录然后连不上 Chrome**——Chrome 集成需要 claude.ai 账号登录
2. **Chrome 设成默认开启却很少用**——浏览器工具一直占上下文,按需 `--chrome`
3. **让它把整个控制台日志拉回来**——告诉它要找什么,日志太长会淹没上下文
4. **在 Chrome 里让它做支付、删除这类操作不加确认**——它会在登录页和验证码前停下,但不可逆操作要你自己把关
5. **以为 computer use 在沙箱里**——它在你真实的桌面上
6. **在 Linux 或 Windows 的 CLI 里找 computer use**——CLI 只支持 macOS,Windows 用 Desktop App
7. **新会话里说"更新那个看板"**——它不知道是哪个,会新建一个。给它链接
8. **把 artifact 当网站部署用**——没有后端、单页,真正的工具部署到自己的基础设施
9. **分享 connector 看板后同事说没数据**——数据用的是查看者自己的账号和 connector
10. **把敏感数据做成 artifact 后公开分享**——公开链接任何人都能打开,分享前确认内容
