# Claude / Anthropic 生态实战写作计划

> AI 系列已经讲过 Prompt / Agent / MCP 协议这层"通用 LLM 工程",这里收窄到 **Claude / Anthropic 生态的下游应用**——Claude Code 怎么用到顶、Claude API 怎么写进产品、Agent SDK 和 MCP 怎么搭成自己的系统。

---

## 时间基线

本系列按 **2026 年 10 月** 的产品状态编写:

- Claude Code 2.1.30x(原生二进制发行,Windows 不再依赖 Git Bash)
- 模型以 Claude 5.x 代为主:Claude Opus 5.5、Claude Sonnet 5.5、Claude Haiku 5.5、Claude Fable 5.1
- Claude API 的 thinking 只用 adaptive + effort,`budget_tokens` 在新模型上已移除

这个领域每周都在变。**命令、字段、价格以官方文档为准**,文中给出的是心智模型和截至基线时的具体用法。

---

## 设计思路

七层结构,对应不同深度的需求:

```
用 Claude Code → 扩展 Claude Code → 并行、自动化与多端
   → Claude API → Agent SDK → MCP Server 开发 → 设计与团队落地
```

不重复 AI 系列已讲过的内容(Prompt Engineering、Tool Use 通用概念、MCP 协议本身),而是聚焦"在 Claude 这一家上怎么用、怎么落地"。

## 每层的边界

| 层 | 回答的问题 | 不讲什么 |
| --- | --- | --- |
| 用 Claude Code | 装好、配好、每天怎么用得顺 | 扩展机制的写法 |
| 扩展 Claude Code | 怎么把团队知识和流程装进去 | 跨会话、跨机器的编排 |
| 并行、自动化与多端 | 多个 Claude 同时干活、离开电脑也在干活 | API 层的实现细节 |
| Claude API | 把 Claude 当能力组件写进自己的产品 | Claude Code 本身 |
| Agent SDK | 用 Claude Code 的内核搭自己的 Agent | 托管部署(见 31 Managed Agents) |
| MCP Server 开发 | 给 Claude 写团队自己的工具 | MCP 协议原理(见 aiLearning/30) |
| 设计与团队落地 | 选型、组合、上线、治理 | 单个功能的用法 |
