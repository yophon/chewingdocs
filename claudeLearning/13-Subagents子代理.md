# Subagents 子代理

05 篇说过,上下文窗口是 Claude Code 最稀缺的资源。子代理就是保护这个资源的主要手段:**它在自己独立的上下文里干活,只把结论带回主对话**。读几十个文件、跑一堆命令、翻大量日志——这些过程留在子代理那里,主对话只收到一段总结。

> 一句话先记住:**子代理用来"隔离过程",不是用来"分担思考"**。当一个子任务会产出大量你之后不会再看的中间内容(搜索结果、日志、文件内容)时,就交给子代理。需要频繁来回讨论、各阶段共享大量上下文的工作,留在主对话里。

---

## 一、子代理带来什么

- **保护上下文**:探索和实现的过程不进主对话
- **约束能力**:限制它能用哪些工具,比如只读
- **复用配置**:个人层的子代理在所有项目里都能用
- **专门化**:针对某个领域写专门的系统提示
- **控制成本**:把读文件、检索这类活交给 Haiku 这样更便宜的模型

代价也要知道:**子代理的请求和主对话计入同一个用量额度**;非 fork 的子代理从零开始,需要时间重新收集上下文,所以有延迟。

---

## 二、内置子代理

| 子代理 | 工具 | 模型 | 用途 |
| --- | --- | --- | --- |
| **Explore** | 只读(禁止 Write、Edit) | 跟随主对话(主对话用 Fable 时,订阅和 Console 账号上改用 Opus) | 找文件、搜代码、理解代码库;调用时会指定 quick / medium / very thorough 三档深度 |
| **Plan** | 只读 | 跟随主对话 | plan mode 下调研代码库 |
| **general-purpose** | 所有子代理可用的工具 | 跟随主对话 | 既要探索又要修改的多步骤任务 |
| **claude** | 所有子代理可用的工具 | 按子代理模型规则 | 没有更合适的专门子代理时的兜底 |

另外还有 `statusline-setup`、`claude-code-guide` 这类专用的辅助子代理,通常自动调用。

**Explore 和 Plan 启动时不加载 CLAUDE.md 和 git 状态**,以保持调研又快又便宜。想让探索跑在更便宜的模型上,自己定义一个叫 `Explore` 的子代理并设 `model: haiku`,它会覆盖内置的那个。

## 三、自定义子代理

### 3.1 最快的方式:让 Claude 写

```
在 ~/.claude/agents/ 里创建一个个人用的 code-improver 子代理,
扫描文件并给出可读性、性能、最佳实践方面的改进建议。
每个问题都要说明原因、给出当前代码和改进后的代码。只读,用 Sonnet。
```

它会生成这样的文件:

```markdown
---
name: code-improver
description: 扫描代码并给出可读性、性能和最佳实践方面的改进建议。写完或修改代码后使用。
tools: Read, Grep, Glob
model: sonnet
---
你是代码改进专家。对每个发现的问题,说明原因,展示当前代码,并给出改进后的版本。
```

**正文就是子代理的系统提示**——它替换的是 Claude Code 的默认系统提示,而不是追加。

### 3.2 放在哪

| 位置 | 范围 | 优先级 |
| --- | --- | --- |
| managed settings 目录 | 整个组织 | 1(最高) |
| `--agents` 参数(JSON) | 本次会话 | 2 |
| `.claude/agents/` | 当前项目,可提交共享 | 3 |
| `~/.claude/agents/` | 你的所有项目 | 4 |
| 插件的 `agents/` 目录 | 启用插件时 | 5 |

目录会递归扫描,可以用子文件夹组织;`name` 在整棵目录树里要唯一。临时测试可以直接在命令行定义:

```bash
claude --agents '{
  "code-reviewer": {
    "description": "代码审查专家。代码改动后主动使用。",
    "prompt": "你是资深代码审查者,关注质量、安全和最佳实践。",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  }
}'
```

> 插件提供的子代理出于安全原因**不支持** `hooks`、`mcpServers`、`permissionMode` 字段。需要这些就把文件复制到 `.claude/agents/` 里。

### 3.3 frontmatter 字段

只有 `name` 和 `description` 是必需的。字段名用驼峰写法,**写错会被静默忽略**。

| 字段 | 作用 |
| --- | --- |
| `name` | 唯一标识 |
| `description` | **Claude 据此决定何时委派**。想让它主动用,写上"use proactively"之类的字样 |
| `tools` / `disallowedTools` | 工具白名单 / 黑名单,同时设置时先应用黑名单 |
| `model` | `sonnet` / `opus` / `haiku` / `fable` / 完整 ID / `inherit` |
| `effort` | 这个子代理的 effort 等级 |
| `permissionMode` | 权限模式 |
| `maxTurns` | 最多跑多少轮,到了就带着"部分完成"标记返回 |
| `skills` | 启动时**完整预加载**的 skills |
| `mcpServers` | 只给这个子代理用的 MCP server |
| `hooks` | 只在这个子代理运行期间生效的 hooks |
| `memory` | 持久记忆:`user` / `project` / `local` |
| `isolation: worktree` | 在临时 git worktree 里运行,和你的工作区隔离 |
| `background` | 即使 Claude 想等它,也保持在后台运行 |
| `omitClaudeMd` | 启动时不加载用户、项目、本地的 CLAUDE.md |
| `autoCompactWindow` | 降低这个子代理的自动压缩窗口 |
| `color` | 在任务列表和记录里的显示颜色 |

所有子代理的描述加起来超过 15,000 token 时,启动会警告——描述要写短。

## 四、能力控制

### 4.1 限制工具

```yaml
---
name: safe-researcher
description: 只读调研
tools: Read, Grep, Glob, Bash
---
```

白名单里没有 MCP 工具,它就用不了任何 MCP 工具。反过来,只想去掉写文件的能力:

```yaml
disallowedTools: Write, Edit
```

注意 `disallowedTools` 里写 `Bash(git push *)` 这种带参数的规则,会**移除整个 Bash 工具**,而不是只禁止 push。

### 4.2 选模型

子代理的模型按这个顺序决定:调用时传入的 `model` 参数 > 定义里的 `model` > `CLAUDE_CODE_SUBAGENT_MODEL` 环境变量 > 主对话的模型。都受组织 `availableModels` 的约束。`/tasks` 里能看到每个子代理实际跑在哪个模型上。

### 4.3 预加载 skills

```yaml
---
name: api-developer
description: 按团队规范实现 API 接口
skills:
  - api-conventions
  - error-handling-patterns
---
实现 API 接口,遵循预加载 skills 里的规范和模式。
```

和主对话里"只放描述、用到才加载"不同,**`skills` 里列的 skill 会在启动时完整注入**。没列的 skill 子代理仍然可以通过 Skill 工具去调用。

### 4.4 持久记忆

```yaml
---
name: code-reviewer
description: 审查代码质量和最佳实践
memory: project
---
你是代码审查者。审查过程中,把发现的模式、约定和反复出现的问题记进你的记忆。
```

| 范围 | 位置 |
| --- | --- |
| `user` | `~/.claude/agent-memory/<名字>/` |
| `project`(推荐) | `.claude/agent-memory/<名字>/`,可提交共享 |
| `local` | `.claude/agent-memory-local/<名字>/`,不提交 |

开启后,它的系统提示里会带上自己 `MEMORY.md` 的前 200 行或 25KB。用的时候可以说"审这个 PR,先查查你的记忆里有没有见过类似的模式",完事后说"把学到的东西存进记忆"。久而久之,它会积累出关于这个代码库的经验。

## 五、怎么调用

| 方式 | 效果 |
| --- | --- |
| **自动委派** | Claude 根据你的请求和子代理的 `description` 自己决定 |
| **自然语言点名** | "用 code-reviewer 子代理看看我最近的改动",Claude 通常会照做 |
| **@ 提及** | 输入 `@` 从列表里选,或手打 `@agent-code-reviewer`。**保证**这次一定用它 |
| **整个会话都是它** | `claude --agent code-reviewer`,或在 settings 里设 `"agent": "code-reviewer"` |

`--agent` 让主线程本身变成这个子代理:用它的工具限制、模型和系统提示。适合"这个项目里我就是要一个只读的审查助手"这类场景。

## 六、前台与后台

- **默认情况下,主对话派出的子代理在后台运行**:你可以继续工作,它完成后结果以通知的形式送达
- 后台子代理需要授权时,弹窗会出现在主会话里,并注明是哪个子代理在问
- 后台子代理使用一个更小的内置工具集
- 子代理面板显示在输入框下方;`/tasks` 查看所有运行中和刚完成的子代理

想让 Claude 等子代理完成再继续(前台运行),要关闭 fork 模式:设 `CLAUDE_CODE_FORK_SUBAGENT=0`。`claude -p` 和 Agent SDK 里 Claude 可以自己决定是否等待。

---

## 七、fork:带着完整对话的子代理

普通子代理从零开始,只拿到 Claude 写给它的委派说明。**fork 则继承整个对话**:同样的系统提示、工具、模型和全部历史。

```
/subtask 根据目前为止对 parser 的改动起草单元测试
```

fork 在后台运行,你继续工作;完成后结果作为一条消息回到主对话。面板里选中它按 `Enter` 能打开它的记录、给它发后续消息,按 `x` 停止。

| | fork | 普通子代理 |
| --- | --- | --- |
| 上下文 | 完整的对话历史 | 只有委派说明 |
| 系统提示和工具 | 和主会话相同 | 来自子代理定义 |
| 适合 | 依赖前面讨论内容的支线任务 | 自包含、能独立说清楚的任务 |

fork 模式默认开启,Claude 也会自己启动 fork。fork 放弃了"输入隔离",但仍然保留了"过程隔离"——它干活的过程不进你的主对话。

---

## 八、启动时子代理能看到什么

普通子代理的初始上下文:

- **它自己的系统提示**(不是 Claude Code 的默认系统提示)
- **委派说明**:Claude 交代任务时写的那段话
- **CLAUDE.md 全套**(Explore、Plan 和设了 `omitClaudeMd` 的除外)
- **git 状态快照**(Explore、Plan 除外)
- **预加载的 skills**
- 命名的子代理还能看到同一会话里其他可以互发消息的 agent 名单

**看不到的**:你的对话历史、你已经调用过的 skills、Claude 已经读过的文件、你的 output style、主对话的 auto memory。

> 所以**委派说明的质量决定了子代理的表现**。如果某条规则必须让子代理知道(比如"不要碰 `vendor/` 目录"),而它又不加载 CLAUDE.md,就要在任务里重申。

## 九、嵌套、并发与恢复

- **嵌套**:子代理默认可以再派子代理,最多三层。用 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 调整,设 `1` 关闭嵌套。适合"审查者为每个发现派一个核实者"这类任务。不想让某个子代理再派,就别给它 `Agent` 工具
- **并发上限**:一个会话里同时运行 20 个子代理时,再派会失败,等数量降下来再说
- **恢复**:每次调用默认是一个新实例。想接着之前的子代理干,让 Claude 恢复它——恢复后保留它完整的历史
- **名字与互发消息**:开启 agent teams 后,Claude 可以给子代理起名,命名的子代理之间能用 `SendMessage` 通信(16 篇)

## 十、安全:子代理的报告会被扫描

子代理可能读过你没审过的文件、网页或命令输出,里面可能藏着针对主对话的指令。所以 Claude Code 会在主对话读取之前**扫描子代理的最终报告**:模仿系统消息格式的内容会被转义,提到 `bypassPermissions` 之类权限设置的会被标记;报告还会带一个标头,声明"这是子代理的话,不代表用户授权"。

这不改变权限:报告引导 Claude 发起的任何工具调用,照样要过权限检查。

## 十一、什么时候用子代理

| 用主对话 | 用子代理 |
| --- | --- |
| 需要频繁来回、反复打磨 | 会产出大量你不需要的中间输出 |
| 计划、实现、测试几个阶段共享大量上下文 | 想强制特定的工具限制 |
| 快速的小改动 | 工作是自包含的,能用一段总结交差 |
| 对延迟敏感 | 想把便宜的活交给便宜的模型 |

另外两个替代选择:

- **想复用一段提示或流程,但在主对话里执行** → skill
- **问一个关于已有对话内容的问题** → `/btw`,它能看到完整上下文但没有工具,答案不进历史

### 常见模式

- **隔离高输出量的操作**:跑测试套件、扫日志、分析大文件
- **并行调研**:同时派几个子代理分别调查不同模块,最后汇总
- **串联**:一个子代理找问题,另一个修,第三个验证

需要几十上百个子代理协同的规模,用 17 篇的 dynamic workflows。

## 十二、踩坑

1. **description 写得含糊**——Claude 不知道什么时候该派给它。写清楚做什么、什么时候用
2. **委派说明不完整**——子代理看不到你的对话,该交代的背景要在任务里写明
3. **以为 Explore 遵守 CLAUDE.md**——它不加载。关键规则要在委派里重申
4. **用 `disallowedTools: Bash(git push *)` 只想禁 push**——会移除整个 Bash
5. **频繁来回的工作也交给子代理**——每次从零开始,来回的成本比在主对话里高得多
6. **以为后台子代理的修改能用检查点撤销**——后台运行的修改不在你的检查点里
7. **给插件子代理写 `hooks` 或 `mcpServers`**——被忽略,复制到 `.claude/agents/` 才生效
8. **子代理越定义越多**——所有描述每轮都占上下文,超过 15,000 token 会警告
9. **完全信任子代理的报告**——它可能读到了恶意内容。重要结论自己核实
10. **嵌套太深**——每层都在消耗额度,大规模并行改用 workflows
