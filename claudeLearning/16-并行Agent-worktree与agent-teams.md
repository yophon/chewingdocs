# 并行 Agent:worktree、agent view 与 agent teams

一个会话一次只能推进一件事。当你手上同时有三件互不相干的活——修一个 bug、审一个 PR、查一个不稳定的测试——最直接的提速方式就是**让三个 Claude 同时干**。这一篇讲 Claude Code 里让多个 agent 并行工作的几种方式,以及它们背后共用的两个基础设施:隔离文件改动的 **worktree** 和让会话互相传话的**跨会话消息**。

> 一句话先记住:**选并行方式看三个问题——谁来协调、工人之间要不要说话、它们改不改同一批文件**。你派活自己检查用 agent view;让 Claude 拆任务、分配、监督用 agent teams;规模大到要脚本来编排用 17 篇的 workflows。改同一个仓库的,一律用 worktree 隔开。

---

## 一、五种并行方式

| 方式 | 是什么 | 适合 |
| --- | --- | --- |
| **Subagents**(13 篇) | 一个会话里派出的工人,在自己的上下文里干完回一段总结 | 支线任务会用搜索结果、日志淹没主对话 |
| **Agent view** | 一个界面派发和监控一堆后台会话(研究预览) | 好几件独立的事,交出去、扫一眼状态、需要时再介入 |
| **Agent teams** | 一个 lead 带多个队友,共享任务清单、互相发消息(实验性,默认关闭) | 让 Claude 自己拆分项目、分配任务、让队友协作 |
| **Projects**(19、20 篇) | claude.ai/code 或 Desktop 里的一个长期对话,Claude 在云端起多个并行线程 | 一大块持续的工作,交给 Claude 统筹 |
| **Dynamic workflows**(17 篇) | Claude 写一个脚本编排大量子代理,并交叉核验结果 | 规模超出几个子代理能协调的范围 |

另外三个配套工具:

- **Worktree**:给每个会话一份独立的 git 检出,并行改文件互不冲突
- **跨会话消息**:让 Claude 列出并给你的其他会话发消息,本机、别的机器、云端都行
- **`/batch`**:一个内置 skill,把一个大改动拆成 5 到 30 个在各自 worktree 里运行的子代理。它是子代理 + worktree 的打包用法,不是单独的协调方式

> 无论哪种方式,**并行都会让 token 用量成倍增加**。三个会话就是三份上下文、三份请求。

## 二、Worktree:并行的地基

### 2.1 为什么需要

两个会话在同一个目录里同时改文件,迟早会互相覆盖。git worktree 是同一个仓库的另一个工作目录:**自己的文件和分支,共享同一份历史和 remote**。每个会话一个 worktree,就各改各的。

### 2.2 启动

```bash
claude --worktree feature-auth     # 或 -w
```

- 在仓库根的 `.claude/worktrees/feature-auth/` 创建,分支名 `worktree-feature-auth`
- 不给名字会自动生成一个,如 `bright-running-fox`
- 在另一个终端用不同名字再开一个,就是第二个隔离会话
- 把 `.claude/worktrees/` 加进 `.gitignore`

也可以在会话里说"在 worktree 里做",Claude 会用 `EnterWorktree` 工具创建并切进去。

**从 PR 创建**:

```bash
claude --worktree "#1234"          # 或直接给 GitHub PR / GitLab MR 的链接
```

### 2.3 基于哪个分支

默认 `"fresh"`:从远程默认分支(通常是 `main`)创建,得到一个干净的起点。需要带上你本地未推送的提交(比如让子代理在进行中的功能分支上干活),设:

```json
{ "worktree": { "baseRef": "head" } }
```

### 2.4 新 worktree 缺少的东西

worktree 是全新的检出,**被 gitignore 的文件不会在里面**——`.env`、本地配置都没有,依赖也要重新装。在项目根放一个 `.worktreeinclude`(gitignore 语法),创建 worktree 时自动复制:

```
.env
.env.local
config/secrets.json
```

只会复制"匹配这些模式**并且**被 gitignore 的"文件,已跟踪的文件不会重复复制。

### 2.5 和主检出共享的东西

- 仓库的 `.git` 目录(提交、分支都是共享的)
- 项目作用域安装的插件
- **权限批准**:在 worktree 里点"不再询问",规则存进主检出的 `settings.local.json`,所有 worktree 生效
- 被 gitignore 掉的 `.claude/skills`、`agents`、`commands`,会从主检出读取

注意 hook 里的 `${CLAUDE_PROJECT_DIR}` **不会跟着进 worktree**,仍指向会话启动时的项目根;hook 想知道 worktree 路径,读输入 JSON 里的 `cwd`。

### 2.6 清理

退出交互式 worktree 会话时,Claude 会检查有没有会被删掉的工作:

- **干净的**:未命名会话自动删除 worktree 和分支;命名会话会先问你
- **有改动或新提交**:问你保留还是删除;保留的话,退出时会打印恢复命令 `claude --worktree <名字> --resume`
- `-p` 运行没有退出提示,**不会自动清理**,`.claude/worktrees/` 可能越积越多

### 2.7 给子代理用 worktree

```markdown
---
name: refactorer
description: 在大量文件上执行机械式重构
isolation: worktree
---
在所有受影响的文件上执行要求的重构,然后跑测试并报告结果。
```

或者直接对 Claude 说"让你的子代理用 worktree"。子代理完成且没有改动时,它的 worktree 自动删除。

## 三、Agent view:一个界面管一堆后台会话

### 3.1 基本循环

```bash
claude agents
```

打开后底部是输入框,上面是会话表格:

1. **派发**:输入一个任务描述,回车,一个新的后台会话就开始了。**每次回车都是一个新会话**,不是给上一个发后续消息
2. **观察**:每行的图标颜色表示状态
3. **偷看并回复**:选中一行按 `Space`,看它最近的输出或它在等你回答的问题,直接在面板里回复
4. **接入**:`Enter` 或 `→` 接入完整对话,在空输入框按 `←` 退回表格

| 状态 | 含义 |
| --- | --- |
| Working(动画) | 正在跑工具或生成回复 |
| Needs input(黄) | 等你:回答问题、授权、或其他只有你能给的输入 |
| Idle(暗) | 没事做,等下一个指令 |
| Completed(绿) | 任务成功完成 |
| Failed(红) | 出错结束 |
| Stopped(灰) | 被你停止,或进程被外部结束 |

行尾的 `#N` 是这个会话关联的 PR。

### 3.2 后台会话的特点

- **不需要任何终端开着**:一个独立的守护进程托管它们。关掉 agent view、关掉 shell,工作照常继续;机器休眠唤醒后也会恢复
- **自动进 worktree**:派发的会话在改文件之前会先移进一个独立的 git worktree,所以并行会话不会互相踩
- **保护成果**:在 worktree 里改了代码的后台会话,结束前会被要求保存成果——提交并推送分支,需要时开一个 draft PR。**不会推 main/master、不会强推、不会合并**。如果你的 CLAUDE.md 说提交由你自己负责,它就不碰 git

### 3.3 其他入口

```bash
claude --bg "调查 SettingsChangeDetector 测试不稳定的原因"     # 直接派到后台
claude --agent code-reviewer --bg "处理 PR 1234 的评审意见"     # 以某个子代理身份运行
claude agents --json                                           # 脚本读取会话状态
```

已经开着的普通会话,输入 `/bg`,或在空输入框按 `←`,就能把它送进后台并打开 agent view。底部的 `← 2 agents` 提示有几个后台会话在等你。

> 每个后台会话独立消耗你的额度。一口气派十个之前,先想想你的额度和限流。

## 四、Agent teams:让 Claude 当组长

### 4.1 和子代理的区别

| | 子代理 | Agent teams |
| --- | --- | --- |
| 上下文 | 独立,结果交回调用者 | 独立,完全分开 |
| 通信 | 只向调用者交结果 | **队友之间直接互发消息** |
| 协调 | 主 agent 管所有事 | 共享任务清单 + 自我协调 |
| 适合 | 只需要结果的专注任务 | 需要讨论、互相质疑、协作的复杂工作 |
| 成本 | 较低 | **高**:每个队友都是一个完整的 Claude 实例 |

### 4.2 开启和使用

实验性功能,默认关闭:

```json
{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }
```

然后用自然语言描述任务和你要的队友:

```
我在设计一个帮开发者追踪代码里 TODO 注释的 CLI 工具。
派三个队友从不同角度探索:一个负责用户体验,一个负责技术架构,
一个专门唱反调。
```

lead 会建立共享任务清单、派出队友、让它们各自探索、汇总结论。只能在交互式会话里组队;`-p` 和 Agent SDK 里不会派队友。

### 4.3 结构

| 组件 | 作用 |
| --- | --- |
| **Team lead** | 你的主会话,派出队友、协调工作 |
| **Teammates** | 独立的 Claude Code 实例,各自领任务 |
| **任务清单** | 共享的工作项,队友认领和完成,依赖关系自动解锁 |
| **Mailbox** | 队友之间的消息系统 |

显示方式:默认 **in-process**,所有队友都在你的终端里,在面板里上下选择、回车查看、直接给它发消息;**split panes** 让每个队友一个窗格,需要 tmux 或装了 `it2` 的 iTerm2,用 `"teammateMode": "auto"` 开启。

### 4.4 用法要点

- **给足上下文**:队友会加载 CLAUDE.md、MCP、skills,但**看不到 lead 的对话历史**,派活时要把背景说清楚
- **团队规模从 3-5 人开始**:token 线性增长,协调开销也会增加,超过一定人数收益递减。三个专注的队友往往胜过五个分散的
- **任务粒度**:太小协调开销大于收益,太大中途没有检查点。理想是能产出明确交付物的独立单元,每个队友 5-6 个任务
- **避免文件冲突**:队友**不会被放进各自的 worktree**,要按文件划分工作
- **lead 自己开始干活了**:提醒它"等队友完成任务再继续"
- **先从调研和审查入手**:并行审查代码、用相互竞争的假设调查 bug,是最能体现团队价值的场景

### 4.5 权限

- 队友继承 lead 的权限模式(`dontAsk` 除外)
- **队友的授权弹窗出现在 lead 会话里**,由你批准
- 队友之间的消息会被标明"来自另一个 Claude 会话,不是用户":**它不能代你批准任何授权**。auto mode 下分类器会审查每条队友消息,并把消息里转述的"已批准"当作不可信内容

## 五、跨会话消息:让你自己开的会话互相传话

### 5.1 用法

你在不同终端开了几个会话,其中一个发现了另一个需要知道的事——不用你在终端之间复制粘贴:

```
问一下另一个终端里那个会话,数据库迁移跑完了没有
把我们刚才做的改动讲给负责支付 API 的那个会话听
告诉 @api-worker schema 迁移已经完成
```

Claude 用 `ListAgents` 找到目标,用 `SendMessage` 发送,内容由它自己写。`@` 加会话名的前几个字母可以从补全列表里选目标。也可以让它"等那个会话空闲时通知我一次"。

**消息只是一段文字**,不会传对话历史或文件。要转移整个上下文,用恢复会话。

### 5.2 能发到哪

| 目标在哪 | 怎么传 |
| --- | --- |
| 本机 | 本地 socket(Windows 是命名管道),**不经过 Anthropic 服务器** |
| 你的另一台机器 | 经 Anthropic 服务器,通过那台机器的 Remote Control 连接送达 |
| 云端会话 | 经 Anthropic 服务器直接送达 |

容器里的会话和宿主机上的会话互相够不着。想让消息离开本机前先经过你确认,设 `isolatePeerMachines`。

### 5.3 收到的消息能做什么

Claude Code 会告诉接收方"这条消息来自另一个会话,不是用户",并且:

- **不能批准任何东西**,不能代你回答授权弹窗
- **不能改配置**:不会因为另一个会话要求就改权限、CLAUDE.md
- **命令不执行**:消息里的 `/compact` 只是文字
- 需要权限的操作照常弹窗

用 `crossSessionInbound` 控制收到消息时怎么处理:`accept` 直接送达、`hold` 只提示不送达、`refuse` 丢弃;也可以在 `/config` 的 "Messages from your other sessions" 里选。

## 六、怎么选

| 情况 | 选 |
| --- | --- |
| 当前任务里有一块会产生大量输出的支线 | 子代理 |
| 三五件独立的事,交出去,回头检查 | agent view(`claude --bg`) |
| 一个功能拆成几块,需要互相讨论和质疑 | agent teams |
| 自己开了几个终端,偶尔需要通个气 | 跨会话消息 |
| 一个大的机械改动,拆成几十份并行 | `/batch` 或 workflows |
| 几百个文件的审计、需要交叉核验 | dynamic workflows(17 篇) |
| 离开电脑也要持续推进的一大块工作 | Projects / 云端会话(19 篇) |

查看正在跑的东西:`claude agents` 看后台会话,`/tasks` 看当前会话里的后台任务和子代理,`/workflows` 看 workflow 运行情况。

## 七、踩坑

1. **两个会话在同一个目录里同时改文件**——迟早互相覆盖。用 worktree
2. **新 worktree 里跑不起来**——`.env` 和依赖都没有。配 `.worktreeinclude`,让它先装依赖
3. **`-p` 跑完 worktree 越积越多**——非交互运行不清理,定期手动清
4. **在 agent view 里回车以为是给上一个会话发消息**——每次回车都是新会话,回复要用 `Space` 打开的面板
5. **agent teams 一开就是七八个队友**——成本线性增长,协调开销更大。从 3 个开始
6. **队友改同一个文件**——它们不在各自的 worktree 里,要按文件分工
7. **派活不交代背景**——队友和子代理都看不到你的对话历史
8. **以为另一个会话的消息能替你批准操作**——不能,任何会话间消息都不代表你的授权
9. **在 hook 里用 `${CLAUDE_PROJECT_DIR}` 找 worktree**——它不跟着进 worktree,读输入里的 `cwd`
10. **并行任务一多就忘了额度**——每个会话、每个队友都在独立消耗,先算账再派
