# 工具与权限规则

Claude Code 能做的每一件事,最后都落到一次工具调用上:读文件是 `Read`,改代码是 `Edit`,跑测试是 `Bash`。所以想控制它能做什么,控制的其实是**哪些工具调用可以直接执行、哪些要问你、哪些一律拒绝**。这一篇先讲清楚有哪些工具、各自有哪些隐含行为,再讲权限规则怎么写。

> 一句话先记住:**权限规则是 harness 执行的,不是模型遵守的**。在 CLAUDE.md 里写"不要读 `.env`"只是一个请求,模型可能照做也可能绕过去;写一条 `Read(./.env)` 拒绝规则,这个读取就根本发不出去。

---

## 一、内置工具全景

| 类别 | 工具 | 是否需要授权 |
| --- | --- | --- |
| **文件** | `Read`、`Edit`、`Write`、`NotebookEdit` | Read 不需要(工作目录内);改动类需要 |
| **搜索** | `Glob`、`Grep`、`LSP` | 不需要 |
| **执行** | `Bash`、`PowerShell`、`Monitor`(后台跑命令,把每行输出喂回来) | 需要 |
| **Web** | `WebFetch`、`WebSearch` | 需要(部分文档域名预先放行) |
| **编排** | `Agent`(派子代理)、`Skill`、`Workflow`、`AskUserQuestion`、`TaskCreate` 等任务清单工具、`EnterPlanMode` / `ExitPlanMode`、`EnterWorktree` / `ExitWorktree`、`ToolSearch` | 大多不需要;Skill、Workflow、ExitPlanMode 需要 |
| **跨会话** | `SendMessage`、`ListAgents` | — |
| **定时与通知** | `CronCreate` / `CronList` / `CronDelete`、`ScheduleWakeup`、`RemoteTrigger`、`PushNotification` | 不需要 |
| **产出** | `Artifact`(发布网页)、`SendUserFile`(把文件发给你) | — |

你不需要记住这张表,日常也不用点名工具,Claude 自己会选。**你需要工具名的场合只有一个:写规则的时候**——权限规则、`--allowedTools` 参数、skill 的 `allowed-tools`、hook 的匹配条件,用的都是同一套 `工具名(参数)` 格式。

想知道当前会话到底加载了哪些工具,直接问它"What tools do you have access to?";MCP 工具的精确名字用 `/mcp` 看。

## 二、文件工具的隐含规则

### 2.1 Read

- 只读文件不读目录,列目录它会用 `ls`
- 单次最多返回约 25,000 token;整个文件超过 256KB 时必须分页读(`offset` + `limit`)
- **图片**会作为视觉内容交给模型,大图会被缩放;要看细节,让它先裁剪再读
- **PDF** 超过 10 页按页码范围读,每次最多 20 页,需要系统里有 poppler 的 `pdftoppm`
- **Jupyter notebook** 返回所有 cell 和输出
- `.xlsx`、`.parquet`、`.zip` 这类二进制格式会被拒绝,它会改用脚本或对应的 skill 去读

### 2.2 Edit

Edit 是**精确字符串替换**:给一段 `old_string`,换成 `new_string`。没有正则,没有模糊匹配。要成功必须满足:

1. **先读后改**:当前对话里读过这个文件(较新的模型在读取本身不需要授权时可以免读直接改)
2. **完全匹配**:差一个空格、一级缩进都会失败
3. **唯一**:`old_string` 必须只出现一次;出现多次就要带更多上下文,或者用 `replace_all`

用 `cat`、`head`、`sed -n`、`grep` 在单个文件上看过,也算"读过"。

### 2.3 Write

Write 是**整文件覆盖**,不追加也不合并。新建文件不需要先读;覆盖已有文件的规则和 Edit 一样。局部修改它会用 Edit,不会用 Write。

## 三、搜索:Glob 和 Grep 默认不在了?

这是近一年最容易让老用户困惑的变化:

- **Windows 上**,Glob 和 Grep 在默认工具集里
- **macOS、Linux、WSL 上**,默认**不提供** Glob 和 Grep,Claude 通过 Bash 调用 `find` 和 `grep`——在 Claude 的 shell 里,这两个命令跑的是 Claude Code 内嵌的实现

以前的建议是"别让 Claude 用 find / grep,用专门的工具";现在在类 Unix 系统上,**用 shell 搜索就是默认路径**。以下情况 Glob / Grep 会回来:

- 启动时用 `--tools` 或 `--allowedTools` 点名了它们
- 拒绝规则或 `--disallowedTools` 把 Bash 整个移除了
- 子代理的 `tools` 字段列了 Glob / Grep 而没列 Bash(只对那个子代理生效)

两个工具的差异要知道:

| | Glob | Grep |
| --- | --- | --- |
| 干什么 | 按文件名模式找文件 | 按内容搜行 |
| 语法 | 标准 glob,支持 `**` | ripgrep 正则(不是 POSIX grep),`interface{}` 要写成 `interface\{\}` |
| `.gitignore` | 默认**不遵守** | 默认遵守 |
| 结果 | 按修改时间排序,最多 100 个 | 三种模式:文件列表(默认)/ 匹配行 / 计数 |

要做符号级导航(跳定义、找引用、看类型错误),装对应语言的代码智能插件,让 `LSP` 工具生效(14 篇)。

## 四、Bash 的几个非显然行为

1. **每条命令是独立进程**。`export` 的环境变量下一条命令就没了。要让变量持久,启动前设 `CLAUDE_ENV_FILE` 指向一个脚本,或用 `SessionStart` hook 写入
2. **`cd` 会延续,但有边界**。在项目目录和附加目录内 `cd`,后续命令沿用;`cd` 出界会被重置回项目目录,并在结果里注明
3. **你的 alias 和函数可用**。会话开始时它会 source 你的 `~/.zshrc` / `~/.bashrc`,把 alias、函数、shell 选项应用到每条命令。**虚拟环境要在启动 Claude Code 之前激活**
4. **超时**:默认 2 分钟,上限 10 分钟,由 `BASH_DEFAULT_TIMEOUT_MS` / `BASH_MAX_TIMEOUT_MS` 控制。前台命令超时**不会被杀,而是转到后台**继续跑(`sleep` 开头的除外)
5. **后台任务**:起 dev server、watch 构建会用 `run_in_background`,用 `/tasks` 查看和停止。无人值守的会话(`-p`、SDK、CI、云端)里后台命令有时间上限:默认 30 分钟,最长 2 小时
6. **输出截断**:成功的结果内联约 30,000 字符,更长的写进文件、给一段预览,Claude 需要时再去读;失败的结果只保留头尾约 10,000 字符

Windows 上没有 Git Bash 时,命令走 `PowerShell` 工具。装了 Git Bash 时两个工具并存,这时要注意:**任何一条 Bash 拒绝规则(哪怕只是 `Bash(git push *)`)都会让整个 PowerShell 工具被关掉**,因为 Bash 规则管不到 PowerShell,Claude Code 宁可关掉也不留一个绕过口。想保留 PowerShell,就为它写对应的规则,比如再加一条 `PowerShell(git push *)` 拒绝。

## 五、权限规则的语法

### 5.1 三种规则与求值顺序

```json
{
  "permissions": {
    "allow": ["Bash(npm run *)", "Bash(git commit *)"],
    "ask":   ["Bash(git push *)"],
    "deny":  ["Read(./.env)", "Read(./secrets/**)"]
  }
}
```

**求值顺序固定:先 deny,再 ask,最后 allow。第一个命中的决定结果,规则写得多具体都不改变这个顺序。**

这意味着:

- `deny: Bash(aws *)` 会拦住所有 aws 命令,哪怕你另写了 `allow: Bash(aws s3 ls)`——**allow 没法在 deny 里开例外**
- 只写工具名的 deny(比如 `"WebSearch"`)会把这个工具**从模型的上下文里整个移除**,它根本看不到这个工具

### 5.2 各工具的规则格式

| 写法 | 作用于 | 匹配方式 |
| --- | --- | --- |
| `Bash(npm run *)` | Bash、Monitor | 命令文本 |
| `PowerShell(Get-ChildItem *)` | PowerShell | 命令文本 |
| `Read(~/secrets/**)` | Read、Grep、Glob、LSP | 路径(gitignore 语法) |
| `Edit(/src/**)` | Edit、Write、NotebookEdit | 路径(gitignore 语法) |
| `WebFetch(domain:example.com)` | WebFetch | 域名 |
| `Skill(deploy *)` | Skill | skill 名 |
| `Agent(Explore)` | Agent | 子代理类型 |
| `mcp__github__*` | MCP 工具 | 工具全名 |
| `WebSearch` | WebSearch | 只能整体允许或拒绝 |

`Edit(...)` 的 allow 同时授予该路径的读权限;`Read(...)` 的 deny 同时禁止 Edit 和 Write 改这个路径。

### 5.3 通配符 `*`

`*` 可以放在任何位置,匹配任意文本(包括空格):

| 规则 | 能匹配 | 匹配不到 |
| --- | --- | --- |
| `Bash(npm run build)` | `npm run build` | `npm run build --watch` |
| `Bash(npm run *)` | `npm run build`、`npm run test --watch`、`npm run` | `npm install` |
| `Bash(git log * main)` | `git log --oneline main` | `git log main` |
| `Bash(ls *)` | `ls`、`ls -la` | `lsof` |
| `Bash(ls*)` | `ls -la`、`lsof` | — |

三条要点:

1. **`*` 要放在子命令后面**。`Bash(git * main)` 会匹配所有 git 子命令,包括能执行任意程序的 `git -c ...`,这通常不是你想要的
2. **结尾带空格的 `*` 也匹配裸命令**:`Bash(ls *)` 能匹配 `ls`
3. 旧写法 `Bash(ls:*)` 等价于 `Bash(ls *)`,但 `:*` 只在结尾有效

### 5.4 按参数匹配(只用于 deny 和 ask)

deny 和 ask 规则可以按工具的顶层参数匹配:

| 规则 | 拦住什么 |
| --- | --- |
| `Agent(model:opus)` | 要求用 Opus 跑的子代理 |
| `Agent(isolation:worktree)` | 要求在 git worktree 里跑的子代理 |
| `Bash(run_in_background:true)` | 后台运行的命令 |

**allow 规则不支持参数匹配**——一个参数值合规,不代表整个调用安全。各工具的主内容字段(Bash 的 `command`、Read 的 `file_path` 等)也不能这样匹配,要用各自的专用格式。

deny / ask 还支持工具名通配:`"mcp__*"` 拒绝所有 MCP 工具,`"*"` 匹配所有工具。

## 六、Bash 规则能拦什么、拦不住什么

### 6.1 它比你想的聪明

- **复合命令会被拆开**:`Bash(safe-cmd *)` 不会放行 `safe-cmd && rm -rf ~`。`&&`、`||`、`;`、`|`、`&`、换行都会拆,每一段单独匹配;deny 和 ask 连子 shell、命令替换、`for` 循环体里的命令都会检查
- **常见包装会被剥掉**:`timeout`、`time`、`nice`、`nohup`、`stdbuf`,以及无参数的 `xargs`。所以 `Bash(npm test *)` 也能匹配 `timeout 30 npm test`
- **内置的只读命令免授权**:`ls`、`cat`、`git status` 这类命令在任何模式下都不弹窗(带写入能力的参数或无法解析时例外)
- **危险形态总会询问**:`watch`、`flock` 这类执行包装,`find -exec` / `-delete`,前缀规则都放行不了

### 6.2 它也有拦不住的

规则匹配的是**命令文本**,同一个程序换一种写法就匹配不上:

| 规则 | 拦得住 | 拦不住 |
| --- | --- | --- |
| `Bash(curl *)` | `curl https://example.com` | `/usr/bin/curl ...`、`sh -c 'curl ...'` |
| `Bash(rm *)` | `rm -rf build/` | `/bin/rm -rf build/`、`bash -c 'rm ...'` |
| `Bash(git push *)` | `git push origin main` | `git -C . push origin main` |

> 用参数限定命令的规则很脆弱。`Bash(curl http://github.com/ *)` 想"只允许访问 GitHub",实际上换个参数顺序、加个选项就失效。**真正要按文件和网络限制,用 04 篇的沙箱;要做复杂判断,用 11 篇的 PreToolUse hook**。

## 七、路径规则:最容易写错的地方

Read / Edit 规则用 gitignore 语法,有四种锚点:

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| `//path` | 文件系统根开始的**绝对路径** | `Read(//Users/alice/secrets/**)` |
| `~/path` | 从家目录开始 | `Read(~/Documents/*.pdf)` |
| `/path` | 相对于**这个 settings 文件的来源** | `Edit(/src/**/*.ts)` |
| `path` 或 `./path` | 相对于当前目录 | `Read(*.env)` |

> **`/Users/alice/file` 不是绝对路径**。单斜杠开头锚定在 settings 来源上:写在项目 settings 里指向项目根下的 `Users/alice/file`,写在用户 settings 里指向 `~/.claude/Users/alice/file`。要写绝对路径必须用双斜杠 `//`。

另外两条:

- **只有 `Read(...)` 和 `Edit(...)` 两种路径规则会被检查**。写 `Write(...)`、`Glob(...)` 的路径规则会被接受但永远不生效,启动时会警告
- 路径拒绝规则会作用于 Bash 里它认识的文件命令(`cat`、`head`、`sed`、`tee`)和重定向目标,但**拦不住任意程序**——一个 Python 脚本照样能读那个文件。真要隔离,还是靠沙箱

## 八、工作目录

默认情况下,Claude 能访问启动时所在的目录(主工作目录)。扩展方式:

| 方式 | 时机 |
| --- | --- |
| `claude --add-dir ../shared` | 启动时 |
| `/add-dir ../shared` | 会话中 |
| `permissions.additionalDirectories` | 写进 settings,长期生效 |

两个细节:

- **附加目录只给文件访问权,不加载配置**。用 `--add-dir` 或 `/add-dir` 加的目录会额外加载其中的 skills、命令和子代理;写在 settings 里的 `additionalDirectories` 什么配置都不加载
- **`/cd <path>` 是"搬家",不是"加目录"**。会话保留,但切到新目录的 CLAUDE.md、项目 settings、hooks、`.mcp.json`、插件;新目录没被信任时会先列出它将激活的规则和 hooks 让你审阅

想让文件工具在任何模式下都拒绝工作目录以外的路径,打开 `permissions.blockReadsOutsideWorkingDirectories`。

## 九、日常管理:`/permissions` 与"不再询问"

- **`/permissions`** 列出所有规则和每条规则来自哪个 settings 文件,可以在 Claude 工作时增删,改动立即生效
- **弹窗里选"Yes, and don't ask again"**,规则写进仓库根目录的 `.claude/settings.local.json`(worktree 会解析到主仓库),只对你生效

不同工具的"不再询问"持续时间不同:

| 工具类型 | 不再询问的范围 |
| --- | --- |
| Bash 命令 | 永久,按仓库 + 命令 |
| 文件修改 | 到本次会话结束 |
| WebFetch | 永久,按仓库 + 域名 |
| WebSearch | 永久,按仓库 |

批准复合命令 `git status && npm test` 时,它会为每个需要授权的子命令分别保存规则,而不是保存整条字符串。

## 十、规则、hook、沙箱的分工

| 机制 | 判断依据 | 适合 |
| --- | --- | --- |
| **权限规则** | 工具名 + 命令文本 / 路径 / 域名 | 绝大多数日常放行和拦截 |
| **PreToolUse hook** | 你自己写的任意逻辑 | 规则表达不了的判断,比如"只在 main 分支禁止 push" |
| **沙箱** | 操作系统级的文件和网络限制 | 不依赖命令写法的硬隔离 |

优先级上,**hook 放行不了规则拒绝的东西**:deny 规则照样拦,ask 规则照样问;反过来,hook 用退出码 2 阻断的调用,allow 规则也救不回来。

---

## 十一、踩坑

1. **以为 allow 能在 deny 里开例外**——不能。deny 永远先于 allow,想要例外就把 deny 写窄
2. **用单斜杠写绝对路径**——`Read(/etc/passwd)` 不是你以为的那个路径,绝对路径用 `//`
3. **写 `Write(...)` 路径规则**——不生效。控制写入用 `Edit(...)`
4. **指望 Bash 规则做安全边界**——换个写法就绕过。安全边界交给沙箱
5. **`*` 放在子命令前面**——`Bash(git *)` 等于放行所有 git 子命令,包括 `git -c` 执行任意程序
6. **在 Bash 里 `export` 指望下一条命令还在**——每条命令独立进程,用 `CLAUDE_ENV_FILE` 或 hook
7. **启动 Claude Code 后才激活虚拟环境**——它启动时捕获的环境里没有,先激活再启动
8. **老习惯坚持要 Glob / Grep**——类 Unix 系统上默认就是 shell 搜索,没必要强行开回来
9. **把 `additionalDirectories` 当成"引入另一个项目的配置"**——它只给文件权限,配置要用 `--add-dir` 或 `/cd`
10. **规则越堆越多不审计**——`settings.local.json` 会随着你点"不再询问"不断增长,隔一段时间用 `/permissions` 清理一次
