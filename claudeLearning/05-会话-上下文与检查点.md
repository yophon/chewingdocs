# 会话、上下文与检查点

模型本身不记事。你每发一条消息,Claude Code 都会把**系统提示、项目上下文、之前所有的消息和工具结果**重新打包,发给模型。所以"Claude 记得什么"其实是"这一轮请求里装了什么"。理解这一点,会话恢复、上下文压缩、缓存命中、检查点回退这几件事就都能串起来。

> 一句话先记住:**上下文窗口是 Claude Code 最稀缺的资源**。它决定了 Claude 能同时看到多少东西,也决定了每一轮的成本和速度。会管上下文的人,同样的任务用的 token 更少、结果更稳。

---

## 一、会话:保存、恢复、命名、分叉

### 1.1 会话一直在落盘

你工作时,每条消息、每次工具调用和结果都实时写进本地的 JSONL 文件:

```
~/.claude/projects/<项目路径转换后的名字>/<session-id>.jsonl
```

所以退出、崩溃、甚至 `/clear` 之后,都能回到之前的会话。

### 1.2 恢复会话

| 命令 | 作用 |
| --- | --- |
| `claude --continue` | 打开当前目录最近的会话 |
| `claude --resume` | 打开会话选择器 |
| `claude --resume <名字>` | 直接恢复指定名字的会话 |
| `claude --from-pr <编号>` | 打开和某个 PR 关联的会话 |
| `/resume` | 在会话里切换到另一个会话 |

会话选择器里的几个快捷键很好用:`Space` 预览内容,`/` 搜索(**可以直接粘贴 PR 链接,找到当初创建它的会话**),`Ctrl+A` 看本机所有项目,`Ctrl+W` 看同仓库的所有 worktree,`Ctrl+B` 只看当前分支。

恢复后会还原:对话历史、模型、权限模式、未过期的会话级定时任务、还在进行中的目标(08 篇)。**不会还原的**:启动时传的 `--mcp-config`、`--settings`、`--plugin-dir`、`--add-dir` 等参数——依赖它们的会话,恢复时要再传一遍。崩溃时正在跑的工具调用不会重跑,Claude 会被告知"这一步可能没完成,先检查再继续"。

### 1.3 给会话起名

同时推进好几件事时,名字是找回会话的唯一靠谱办法:

```bash
claude -n auth-refactor      # 启动时起名
/rename auth-refactor        # 会话里改名
claude --resume auth-refactor
```

不起名的会话也会自动得到一个标题(用小模型根据第一条消息生成),同样能用来恢复。接受 plan mode 的方案时,标题会换成根据方案生成的。

### 1.4 分叉:换条路试试,不丢原来的

```
/branch try-streaming-approach
```

`/branch` 把当前对话复制成一个新会话并切进去,原会话原封不动。命令行等价写法是 `claude --continue --fork-session`。

**不分叉、在两个终端里同时恢复同一个会话**,两边的消息会交错写进同一份记录,很快就乱了。想并行,用分叉或者 16 篇讲的 worktree。

### 1.5 回来时的自动回顾

离开终端一段时间(至少三分钟)再回来,Claude Code 会显示一行**会话回顾**,告诉你刚才做到哪了。随时可以用 `/recap` 手动生成。不想要就在 `/config` 里关掉 Session recap。

## 二、上下文窗口里装了什么

### 2.1 你没打字之前就已经占了一部分

会话开始时,下面这些已经进了上下文:

- 系统提示和工具定义
- CLAUDE.md(或 AGENTS.md)、auto memory、不带路径限制的 rules
- MCP 工具的**名字**(完整 schema 按需加载)
- skills 的**描述**(完整内容按需加载)
- output style、`--append-system-prompt` 追加的内容

### 2.2 工作过程中不断增长

- 每读一个文件,内容就追加到对话里
- 读到某个目录下的文件时,该目录的 CLAUDE.md 和匹配路径的 rules 随之加载
- 每次命令输出、hook 返回的附加内容都会进来
- **子代理是例外**:它在自己的上下文里干活,只把总结带回来

### 2.3 用 `/context` 看实际占用

`/context` 按类别列出当前占用,并给出优化建议,还能看到加载了哪些 CLAUDE.md 和 memory 文件。`/context all` 能看每个 MCP 工具占多少 token。

> 养成习惯:**长任务开始前和进行中各看一次 `/context`**。很多"Claude 怎么变笨了"的问题,原因是上下文被一大段无关的日志或文件塞满了。

## 三、上下文满了会怎样:压缩

### 3.1 自动压缩

接近上限时,Claude Code 会**先清理旧的工具输出,不够再把对话总结成摘要**。你的请求和关键代码片段会尽量保留,但早期的详细指令可能丢失。

压缩后哪些东西会恢复:

| 内容 | 压缩后 |
| --- | --- |
| 系统提示、output style | 继续生效 |
| 项目根的 CLAUDE.md、不带路径的 rules、auto memory | 从磁盘重新注入 |
| skills 描述 | 按当前 skills 重建后注入 |
| plan mode 写的方案 | 从磁盘重新注入 |
| 带 `paths:` 的 rules、子目录的 CLAUDE.md | 下次碰到对应文件时再加载 |
| 读过或改过的文件 | 重新读最近修改的最多 5 个(超过 5,000 token 的只给路径) |
| 调用过的 skill 正文 | 重新注入,每个最多 5,000 token,总共最多 25,000 token,最早的先丢 |
| 后台命令和后台子代理 | 继续运行,Claude 会被提醒它们还在跑 |
| hooks 之前追加的内容 | 和其他对话一起被总结 |

几个由此得出的实践:

- **必须一直遵守的规则放项目根的 CLAUDE.md**,不要只在对话里说一遍
- **skill 最重要的指令写在开头**,压缩后超长部分会被截掉
- **一条规则需要跨压缩保留,就别给它加 `paths:`**
- 压缩后想补注入点什么,用匹配 `compact` 来源的 `SessionStart` hook

### 3.2 主动管理

| 做法 | 什么时候用 |
| --- | --- |
| `/compact focus on the auth bug fix` | 开始一段新的长任务前,自己决定摘要保留什么 |
| `/rewind` → Summarize from here / up to here | 只压缩某一段,比如中间那段冗长的调试过程 |
| `/autocompact 500k` | 让它在上下文用到 500K 时就开始压缩,而不是等到上限 |
| `/clear` | 切换到不相关的任务。旧对话只会挤占空间、每轮都花钱 |
| 交给子代理 | 大量阅读、搜索、跑一堆命令看输出 |

也可以在 CLAUDE.md 里加一节 "Compact Instructions",告诉自动压缩该保留什么。

> 如果某个文件或工具输出大到"每次压缩完立刻又满了",Claude Code 尝试几次后会停止自动压缩并报错,而不是无限循环。这时要找出那个巨大的输出源头。

### 3.3 要更大的窗口

Fable 系列、Sonnet 5 及以后、Haiku 5.5、Opus 4.6 及以后、Sonnet 4.6 支持 **100 万 token** 的上下文窗口。但窗口大不等于该塞满:**上下文越长,每轮越贵、越慢,模型在海量内容里找重点也越难**。大窗口用来装确实需要同时看的东西,不是用来逃避管理。

## 四、缓存:为什么有些操作会让下一轮变慢变贵

### 4.1 前缀缓存

每轮请求都会重发完整上下文,但 API 会缓存"和上一轮相同的开头部分"(前缀)。正常对话中,只有最新的一问一答是新内容,其余都从缓存读,又快又便宜。

Claude Code 按变化频率排列请求内容:

| 层 | 内容 | 什么时候变 |
| --- | --- | --- |
| 系统提示 | 核心指令、工具定义 | 加载的工具集变化时 |
| 项目上下文 | CLAUDE.md、auto memory、不带路径的 rules | 会话开始、`/clear`、`/compact` 后 |
| 对话 | 消息、回复、工具结果 | 每一轮 |

**前缀里任何一个字节变了,后面的缓存全部失效**。

### 4.2 会让缓存失效的操作

- **切换模型**(每个模型有自己的缓存);`opusplan` 在进出 plan mode 时会切模型
- **改 effort**:多数模型会失效;Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1 通过 API key 或订阅使用时例外
- **第一次打开 fast mode**
- **连接或移除 MCP server、启用或停用插件、用 deny 规则移除整个工具**(工具定义变了)
- **压缩对话**
- **升级 Claude Code**

### 4.3 不影响缓存的操作

- 改仓库里的文件(Claude Code 只会追加一条"文件已变化"的提醒)
- **会话中途改 CLAUDE.md**——不影响缓存,但**也不会生效**,要 `/clear`、`/compact` 或重启后才读新版本
- 切换权限模式、切换 output style
- 调用 skill 和命令、`/recap`、回退对话、派子代理

> 实践建议:**会话开头定好模型和 effort,任务中途少切换,`/compact` 留到任务之间的自然停顿点**。

### 4.4 缓存能保留多久

缓存在闲置一段时间后过期,每次命中都会重置计时:

| 请求 | 订阅额度内 | 超额计费 / API key / 云厂商 |
| --- | --- | --- |
| 主对话 | 1 小时 | 5 分钟 |
| 子代理、workflows、压缩等 | 5 分钟(少数辅助请求 1 小时) | 5 分钟 |

用 API key 的话,可以在 settings 里设 `"promptCacheTtl": "1h"` 给主对话一小时的缓存。

### 4.5 看缓存效果

`/usage` 的 Session 区块会显示一行缓存统计,比如:

```
Prompt cache (main): 14 requests · 91% of input tokens from cache · 2 misses ...
```

命中率明显偏低,就回头对照 4.2 节,看是不是中途切了模型、加了 MCP server 之类的操作。

## 五、检查点:改坏了怎么回退

### 5.1 自动跟踪

你每发一条开启新一轮的消息,Claude Code 就自动建一个检查点,记录 Claude 用文件工具改过的文件。一个会话保留最近 100 个检查点,恢复会话后依然可用,默认大约 30 天后清理。

### 5.2 回退菜单

`/rewind`,或在输入框为空时**连按两下 `Esc`**,打开回退菜单。选中某条消息后:

| 选项 | 效果 |
| --- | --- |
| **Restore code and conversation** | 代码和对话都回到那一刻 |
| **Restore conversation** | 只回退对话,保留当前代码 |
| **Restore code** | 只回退文件,保留对话 |
| **Summarize from here** | 把这条消息之后的内容压缩成摘要 |
| **Summarize up to here** | 把这条消息之前的内容压缩成摘要 |

如果之前在同一个进程里 `/clear` 过,菜单顶部还会出现一项"previous session",可以回到清空前的对话。

### 5.3 检查点管不到的

| 情况 | 结果 |
| --- | --- |
| **Bash 命令改的文件**(`rm`、`mv`、`cp`、脚本生成) | 不跟踪,撤不回 |
| **子代理的修改** | 通常不在你的检查点里(前台运行的 fork 型 skill 例外) |
| **你自己或其他程序在外部改的文件** | 不跟踪 |
| **数据库、外部 API、部署** | 根本不是文件,撤不回 |
| 符号链接和硬链接 | 恢复时跳过 |

> **检查点不是版本控制的替代品**。它适合"刚才那几步改坏了,退回去换个思路";要长期保留的状态,还是用 git 提交。

## 六、从脚本里拿会话数据

| 需求 | 做法 |
| --- | --- |
| 导出给人看 | `/export`,复制到剪贴板或存成文本文件 |
| 跑一次并拿结构化结果 | `claude -p "..." --output-format json` |
| 向已有会话追问 | `claude -p --resume <session-id> --output-format json "总结一下改了什么" \| jq -r '.result'` |
| 会话结束时归档 | `SessionEnd` hook 读输入里的 `transcript_path` |

## 七、用量:`/usage` 看什么

`/usage` 的 Session 区块显示本次会话的 token 用量、按模型拆分的输入 / 输出 / 缓存读写,以及按标价折算的金额(**订阅用户这个金额不代表实际扣费**,看的是额度消耗)。它还会告诉你哪些 skills、子代理、MCP server 最耗额度。`/clear` 之后开始新会话,统计归零。

## 八、踩坑

1. **一个会话从早用到晚,什么任务都往里塞**——上下文越来越满,模型越来越"笨",每轮越来越贵。任务之间 `/clear`
2. **重要规则只在对话里说了一遍**——压缩后可能丢。写进 CLAUDE.md
3. **会话中途改 CLAUDE.md 指望立刻生效**——要 `/clear` 或 `/compact` 后才读新版本
4. **任务做到一半切模型或切 effort**——整段上下文重新计费。开头定好
5. **以为检查点能撤销 Bash 的改动**——`rm`、`mv`、脚本生成的文件都撤不回
6. **两个终端恢复同一个会话**——消息交错写进同一份记录。用 `/branch` 或 worktree
7. **恢复会话后发现 MCP 工具不见了**——启动时用 `--mcp-config` 传的配置要重新传
8. **把大段日志直接贴进对话**——让 Claude 自己用命令过滤,或者交给子代理读
9. **指望 100 万 token 窗口解决一切**——窗口大不代表注意力也大,该清理还得清理
10. **从不看 `/context`**——上下文被什么占满了都不知道,优化无从下手
